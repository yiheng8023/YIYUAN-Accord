## 每个切片的最小记录

记录在实际工作产物或已有证据旁即可，不再建立一套重复平台：

- 对应 F/W/S/A、任务及预期用户结果；输入、授权、包/提交、宿主版本/入口、模型与相关配置。
- 触发者、执行者、必要状态、失败后的恢复者；有帮助和无帮助的条件分别标明。
- 实际动作、产物和后态；哪些判断错误、如何纠正、哪些旧效果保留。
- 用户参与属于目标取舍、新授权/本人动作，还是可避免催促、纠错、协调、救援；后者不能从自主结果中删除。
- 未完成的覆盖和阻塞、下一有效动作、相关状态与证据位置。

测试条件和评价口径在运行前明确；运行后修改口径必须保留原结果并说明原因，不把失败重新分类成成功。必要信任决定不得为了“零干预”而跳过。

## 原生能力与历史恢复

S2 的实现必须接通 [计划中的自动化路径](PLAN-v3.3.md#自动化如何落地)：实际触发、判断执行、必要状态、存活恢复者、核验收尾。先从所需结果选择能力组合，不先以成本上限或组件数量裁掉功能。若宿主不能承担必要的跨轮唤醒、持久状态或故障续做，应补足相应机制；不要把职责退回提示词后就称已实现。评估者手工启动下一轮只能验证辅助路径，不能代验无人提醒的续做。

先确认必要任务入口职责有可靠的实际连接；不能以偶尔选中 Skill 代替。AI 宿主中的 Agent 承担智能判断与执行，Accord 保留必要职责并接通自动化；详细指导按需加载，工具不必全部经过 Accord 代理。

合理增加调用、状态和运行时投入以实现自动化可以接受；S4 优化的是可用方案中的无效消耗。真实预算冲突应提出具体需要和替代，不能默默减少必要结果，亦不能擅自产生未授权费用。

由 Agent 主动查受支持的实际入口与状态，再判断接口、UI、配置或组合路径能否承担任务；必要时核对官方说明，不以缺少现成工具推断宿主无能力。读取工具目录不等于探索全部宿主，按钮可见不等于已接通执行，也不先建重复的全量静态能力库。原生足够就复用，但要保留结果责任；存在缺口时修复连接或补必要机制。若需用户配置或操作，先核实能否由已有授权下的 Agent 完成，不能把便利问题当成权限问题。

信息不确定或时效性重要时，主动联网核对官方或其它可靠资料；涉及可复用实现、生态方案且有改善任务路线的实质可能时，再去 GitHub 等来源寻找成熟实现，原生能完成不免除该条件下的比较。比较适配、实际效果、维护、许可及授权，再选择复用、组合或实现；保留足以解释决策的来源与理由，避免反复调研。外围生态不只发现，还须在授权内正确启停、复用、回收或退役，验证实际生效与退出后态。

前身系统 调查以用户真实体验对应的提交、宿主与任务记录为目标。候选脚本是线索，不是自动归因；成功、人工救援、失败都保留。取回有效结果与必要机制，不整代恢复已淘汰结构；也不以“精简”预先排除持久状态或运行时。

3.3 不整体推翻历史。修改前识别仍需保留的结果与消费者，修改后验证未受影响效果；保留、修复、替换或退役由当前必要结果决定。

## 排除变量与环境复验

用户已授权开发中按需排除变量。先识别会改变当前切片结论的配置、模型、入口、扩展与观察器因素，优先采用任务级、可回退的局部隔离；不要为“干净环境”重置共享宿主。必要共享调整明确具体范围、原状态备份、受影响任务和恢复路径；真实新增信任、数据访问、费用仍依授权。

隔离结果用于定位原因，修复后回到真实自定义环境复验；分别记录隔离与组合条件，不能用前者代验后者。用户 AGENTS.md 等有效配置参与协作，读取先后不等于授权层级或执行优先级；检查必要职责在相关实质动作前参与并收到动作反馈。ChatGPT 各入口与 Codex Desktop/CLI 等分别核验，不外推接口暴露、权限或实际效果。

## 运行资源与生态生命周期

W02/W06/W07 通过实际可用的操作系统与宿主接口观察 CPU/GPU、RAM/VRAM、磁盘 I/O 与空间，识别进程、终端、浏览器、服务、并发任务和多代理的实际归属及占用。按工作需要和当前负载分配、调整并发、限流、暂停或回收任务资源，随后核验负载恢复、必要状态保留与工作续做；不额外建设宿主已可靠承担的管理器。

先核对既有 resourceStewardship 的当前切片相关实现与宿主控制，再补断点；接口调查足以改变当前决定即可进入实现，不将历史的全量盘点措辞变成长前置。没有独立执行器不证明职责缺失，宿主实际完成也须有动作与后态证据。

在有界、代表性的持续运行与压力条件下核对累积占用，并检查结束、取消和异常退出后的未回收资源；阈值、时长与采样按实际环境确定，不猜通用数字，不为测试拖垮用户环境。资源管理包含运行中调节，不能只在结束时删除文件。未知归属进程不能盲杀，防护不能为便利关闭，也不重置用户环境；不可观察或控制的范围记明实际限制，保留安全续做路线。

生态扩展的可见、已安装、已启用、已使用和仍需保留分别核对。无必要占用时优先按原生能力停用或回收任务暴露，需要时复用；卸载或退役须具有相应授权并验证无关效果保留，防止能力与后台负担无界增长。

## 连续性专项

在普通长任务中观察自主判断；受控事件只验证机制。仅在所选宿主、有效授权下执行必要迁移。若工具明确要求新任务授权，记录该限制，Agent 仍须自主发现需要、准备最小交接并提出具体请求；此结果属于发现完成、执行受限，不称完整自主迁移。

接管顺序：保存最新需求、纠正、真实状态、未完工作及证据定位；目的端独立核对并接受工作，通过实际续做确认接管；确认单写者后来源停止写入。收件回执、摘要生成或新窗口存在都不能代替接管。失败保护最后安全来源和目的端，不重复创建多写者；归档用户任务仍需相应授权。

度量遗失/歪曲的决策与证据、重复劳动、恢复时间/资源、额外用户救援及副作用；明确观察范围，不宣称绝对无损。容量未知时采用短工作段和必要检查点，不猜百分比；健康压缩后继续不算迁移失败，也不能证明自主提前交接。

## 动态纠偏与收尾

功能不工作：先修实际链路，不追加报告凑进度。反复失败或等待互锁：查原因、换有判别力的路径，推进独立工作；不盲目重跑。历史资产有问题：定位消费者，修正、合并或退役当前依赖，保留可靠来源，不把债务留到最终交付。

发生材料性变化后，同步基线事实、计划工作包、实际工序、验收范围和 update plan；只有受影响部分重验。编排记录与产品能力分开，开发助手代办不自动成为插件自主效果。

结束切片前核验产物、受影响回归、未完成项及资源归属；任务所有且不再复用的测试会话按既有明确授权清理或归档，保留必要脱敏证据，不触碰未知/用户工作会话。平台等待记录为等待，不不断轮询或假称后台持续工作。
