# 3.3 基线：恢复并兑现高度自动化

修订：r1 · 2026-09-09。状态：规划基线，功能验收尚未开始。

## 使命与本轮授权

用户专注创造与决策，Agent 承担实现目标所需、已获授权的工作。Accord 与用户、宿主及生态共生协作、各自主权独立。过程管理是支撑手段，不能成为产品结果；少让用户催促、协调、纠错和救场，是必须兑现的功能目标。

本轮用户要求把系统性纠偏加入 3.3，并编写基线、计划、工序和验收标准，随实际工作动态调整。本修订开展文档编制与核对，不代表已经启动产品实现、共享安装、宿主实验或 3.3 发布。先前“纸面计划”的状态不再意味着只保留方向摘要；现在形成可执行规划。现有产品版本、发布标签、代码与安装保持各自身份。

功能实现优先：先让必要功能可用并验证结果和关键失败恢复，再据此完成成本、治理、机制与系统平衡。安全、授权、原始输入保护贯穿实施，但不可把全面治理或资料整理变成长期前置。预算和方法可修订，不能通过降低必要结果要求使检查通过。

用户最新纠正：除了必要人工介入，目标是高度自动化；为此增加合理的计算、状态存储、运行时或维护投入可以是正确选择。本计划中的“减轻负担”首先指用户被迫承担的催促、协调、纠错和救援，不等于最小 Token、最少代码或零运行成本。成本不是必要自动化的否决条件；先实现完整职责，再在保住效果的方案间优化无效消耗。显著新增费用仍须实际授权，不能把价值优先解释成无限支出授权。

## 宿主覆盖边界

“覆盖所有能力、功能、按钮、设置、配置”指建立对实际目标宿主完整可见面的责任覆盖，按任务选择使用；不是每轮点击全部按钮，也不是一张能力名称表就算完成。范围包括模型与推理、多模态、工具与计算机/浏览器操作、文件与网络、执行与并发、任务/会话/上下文、后台与计划任务、插件/Skill/MCP/应用、账户/权限/信任、设置/配置/记忆、安装更新恢复、资源和发布分发；发现新类别必须补入。

逐宿主版本、入口和适用账户条件，记录：官方或实际来源、可发现性、读/执行途径、必要权限、调用者、预期结果、失败及恢复者。明确区分未调查、已发现未执行、已执行未核验、已验证、受限、真实不适用。没有接口、缺账户或没有可靠信号不能写成“不适用”来关闭必要缺口；记录具体阻塞、替代路线与剩余义务。

先从已有 Codex、Claude 的真实入口切入，但不把当前有限支持包装成全部宿主覆盖。其它入口保留待适配项；安装、账户、费用和新宿主实验依具体授权进行。CLI 是无头环境的一等入口，Desktop 的 UI 能力不能替代 CLI；任何入口也不能靠另一入口成功获得通过。

## 三组比较起点

1. 当前宿主原生能力：同类任务、相近条件下实际能做什么。
2. 用户实际用过的 前身系统：先定位真实版本、消息触发和接管记录；无法重放时保留历史观察范围，不伪造等条件对照。
3. 已安装 3.2.1 与未来 3.3 候选：绑定实际包、模型、入口、工具、配置及任务，区分开发者补救与产品自身作用。

没有历史证据不妨碍修复当前已复现缺口；没有因果对照不能声称净收益。替换或删除机制必须保住其仍需结果，减少代码、提示或状态不是独立目标。
