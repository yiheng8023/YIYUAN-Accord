## 使命与本轮授权

职责定位、用户直接操作与必要确认统一见[当前节点](PLAN-v3.3.md#用户操作与环境变化)。Accord 提供持续协作的协调与可靠性保障，插件是交付形式；不强制所有调用中转，也不取得高于用户或宿主的权限。默认非技术用户条件不排斥熟练用户。变化事实、实际影响及意图分别核对，确认后仍需纠正受影响历史并复验；不擅自恢复用户明确选择。开发环境可有自定义和已启用的旧包，验收必须区分开发辅助、待测字节、实际暴露和结果归因。

动态自适应与驱动宿主自举面向实际遇到的环境。借现有获准能力主动建立缺失条件，并验证执行、恢复和结果；不能把可补足条件直接判为“不支持”。开发隔离服务因果定位，不是用户必须恢复默认环境的要求。真实无法补足的能力、权限或资源限制仍须有证据与可行替代分析，启动和失败恢复不能循环依赖尚未具备的最终能力。

F05信号连接增量：所属App Server客户端可通过原生动态工具把通知交给现有助手，窗口观测与未知占用/效率/完整性分开。当前已实测两次显式查询并由Agent正确使用；换轮、reroute、压缩、断连及过期的失效规则有离线反例，真实压缩/模型变化和自主择时仍待验。该适配不等于现装Desktop或ChatGPT入口已自动接通。

F01/F03/F06 输入变化增量：当前源码已将原生 UserPromptSubmit 的 model/permission_mode 及相邻输入差异送入既有入口；缺失保持未知，恢复或中断后的旧观察不作当前值。宿主自动续做遇到条件变化会使旧续做决定失效，保留原用户目标与暂停。一个无预置检查点的原生三轮案例保留未决口径、明确恢复后完成三文件与接口重试，原件、检查点和所属进程后态已核。该观察不证明 Agent 因新字段而改变行为，不覆盖全部设置、中途变化或完整安装包；详见[输入变化记录](PROCEDURE-v3.3.md#原生输入条件变化与暂停恢复2026-09-09)。

对外插件名称统一为 **YIYUAN Accord**，宿主是适配维度，不再进入展示名。现有技术包标识保留兼容；3.3 只绑定 OpenAI 开发包；退出当前分发的适配由旧 Git 版本保留。旧发布名称与证据保留历史身份。

F05的择时必须为下一工作段、交接材料、目标接续验证、失败恢复及安全余量同时留空间；窗口硬上限不能代替经实际任务验证的效率范围。累计/单次token用量和压缩次数都不能直接充当实时占用或损耗。当前助手已提供绑定输入/宿主条件的只读预算评估；测量或估计依据缺失时返回unknown，缩短工作段并提早检查点，不等待耗尽，也不强迫健康载体交接。

入口范围遵循[适用性与版本承诺](PLAN-v3.3.md#入口适用性与版本承诺)：Agent执行入口承担生产交付主线，先按真实用途、必要职责的全链路可行性和全生命周期成本确定开发范围；普通Chat不作为默认独立交付项。网页、云端、插件可安装或是否支持Hook均不能单独决定适用性；当前组件无法直接复用时，比较原生能力、Agent判断、MCP及其它合理组合。辅助对话或执行衔接按其真实价值与职责评价，保留未决前提。此前侧载实验只回答有界兼容性问题，不建立新的适配承诺。

所有功能均由Agent按任务状态和真实需要自主择时调用，并负责后续状态、执行反馈、必要恢复、验证和收尾。fork只是示例；研究、模型选择、协作、上下文处理、工具与生态、资源控制、验证和交付同样适用。用户不应知道工具名或先发操作指令。需要时主动用、无需求时不制造调用；必要职责可靠参与不等于所有功能每轮常开。实际授权、能力及副作用边界继续约束具体动作。

模型调度采用动态发现与协调：模型名称、版本、套餐权限和推理选项都可能变化，按当前账号、实际调用入口、用户限制与任务要求决定候选，不将某模型写成固定最低档或默认下限。本轮按用户要求不选 Spark；这属于当前测试约束，产品不能依赖 Pro 专属选项，也不能把今天的套餐名称永久编码为权限规则。

用户重申旧Bob/Matt讨论已达成的吸收原则：工程判断与可靠性机制是Agent各类工作的横向基础，不只用于写代码；应内化必要能力，也应借力宿主。已从旧Git对象核实2026-07-31的软工原则再验证记录：保留目标保真、正确性、责任、验证、恢复及长期维护的有效要求，具体实践随任务和宿主调整，用结果与反例检验。该历史记录支持方法连续性，不是原谈话逐字来源或旧流程的恢复授权。专业领域正确性仍需对应领域检验；不把通用工程检查当作领域验收。当前实现按实际缺口分工，宿主足够则复用，需要稳定内化的判断/契约/反馈连接就实现，不能借“宿主负责”留下无人执行的职责。

用户确认运行时、状态机及其它结构均为可选手段，按必要结果选择；复用宿主时仍须保有目标、授权、状态解释、核验、暂停和撤回的控制，不能越过宿主实际权限。持久状态、跨任务关联、恢复执行者和再次唤醒分别验收。当前Codex源级检查点已改用稳定用户目录并刷新后再替换文件，旧临时状态保持可见、冲突不自动合并；同一session/cwd的跨进程恢复已有局部验证。它仍不是跨任务接管、无人唤醒或断电持久性的证明，现装包和新源字节亦须分开。

用户进一步明确：其判断同样可质疑和校准，以事实和共同理解约束行动；有界研究先解决影响方案选择的不确定性，不能机械执行或把研究变成每步重复仪式。模型及子代理选择由 Agent 负责，先核实实际接口、可用模型、质量与总成本，再按任务分配；不要求用户会切换模型。必要时可备份并初始化开发变量，但开发对话不得删除；测试按最新授权使用原生临时对话、用完结束。优先可回退的任务隔离。已安装的 Matt Skills 按实际适用性采用，其局限和流程冲突仍须判断。

本次与上轮实现、失败和验证均属于同一个3.3开发目标。全局逻辑和结果依赖先自洽，再按需拆解实施；基线、计划、工序、验收以及相关逻辑、规则和机制随证据联动校准，不冻结方法，也不因局部修订重启目标。方向、原则与方法论未发生实质转向；涉及必要决定或尚不能判明的关键分歧时再共同探讨。

用户不愿阅读资料或学习工具操作也是默认条件。Agent 主动查阅官方资料、GitHub 等，理解比较、给出结论并执行；来源供按需核查，阅读不是使用前置。不得用自行查文档、研究配置或选工具替代完成工作。无法代办的本人动作及关键决定，先准备具体事项，再以简短普通语言说明必要一步，保留真实授权边界。

课程、教程和第三方指导的筛选、核实与适用性判断由 Agent 承担。免费/收费、热度、作者名气和官方推荐都不能单独证明当前任务效果；官方资料用于核实支持范围、接口与明确限制，实用性还需适用条件、可复现结果与总成本。第三方更合适的方法可有界采用。用户获得经筛选验证的方案、结果和影响决定的取舍，不需先学成专家再判断教程是否可信；资料供核查，不成为用户的新作业。

默认用户仅会自然语言输入，可能不知道想法是否可行，不懂工具、配置、并发、资源或上下文，也不会主动 fork、开新任务或救场。用户可以持续在同一对话交流；Agent 主动判断可行性、开展必要研究、说明取舍，完成已授权的执行、纠偏、连续性和收尾。关键决定与必要本人授权仍由用户承担，以普通语言交互；不要求用户代办可由 Agent 完成的技术操作。此条件是普通入口与连续性、资源管理验收的起点，不是已实现的效果。

用户专注创造与决策，Agent 承担实现目标所需、已获授权的工作。Accord 与用户、宿主及生态共生协作、各自主权独立。过程管理是支撑手段，不能成为产品结果；少让用户催促、协调、纠错和救场，是必须兑现的功能目标。

用户已要求把系统性纠偏加入 3.3，建立并动态调整基线、计划、工序和验收标准；现进一步授权交接到新任务继续功能开发，按需排除环境变量影响。3.3 仅交付 ChatGPT/Codex 适用入口，其它适配退出本版分发。本修订进入普通入口运行时切片，当前 Codex 开发身份与历史包身份分别绑定；共享安装、新账户或信任、显著费用及新发布依具体授权。现有产品版本、发布标签、代码与安装保持各自身份。

功能与系统闭环共同构成交付：按最短必要链路实现功能，同时检查共享状态、接口前提、故障传播、恢复执行者和资源归属；组合后失效的功能不算可用。先修影响结果最大的薄弱依赖，关键质量底线不能被其它长项抵消。完整对照与成本评估基于可用实现开展，但耦合风险不能留到最后。安全、授权、原始输入保护贯穿实施，不把全面治理或资料整理变成长期前置。预算和方法可修订，不能通过降低必要结果要求使检查通过。

3.3 不推倒全部历史：保留有效结果、机制与可复用证据，只对受影响的缺口修正、替换或退役。信息不确定或时效性重要时，主动联网核实官方或其它可靠资料；涉及可复用实现、生态方案且有改善任务路线的实质可能时，再去 GitHub 等来源寻找成熟实现，完成有界比较后决定行动。即使原生能完成，也不能跳过后一条件下的比较。调查不是扩展安装或新增权限的授权。

用户最新纠正：除了必要人工介入，目标是高度自动化；为此增加合理的计算、状态存储、运行时或维护投入可以是正确选择。本计划中的“减轻负担”首先指用户被迫承担的催促、协调、纠错和救援，不等于最小 Token、最少代码或零运行成本。成本不是必要自动化的否决条件；先实现完整职责，再在保住效果的方案间优化无效消耗。显著新增费用仍须实际授权，不能把价值优先解释成无限支出授权。

智能判断主要由 AI 宿主中的 Agent 承担，Accord 接通必要的自动化职责：可靠进入任务、承接当前目标与授权、组织执行、接收反馈、纠偏和恢复。必要入口参与不能只靠 Agent 偶尔选择 Skill；详细指导仍按需要加载。Accord 在宿主与生态之间承担逻辑协作职责，不强制代理所有工具，也不接管宿主、用户或扩展的主权。

## 宿主覆盖边界

“覆盖所有能力、功能、按钮、设置、配置”指建立对实际目标宿主完整可见面的责任覆盖，按任务选择使用；不是每轮点击全部按钮，也不是一张能力名称表就算完成。由 Agent 主动发现实际接口、UI、配置及官方说明，尽量复用宿主已有状态、执行与调度，不重复建设全量静态能力库，也不让用户代做可安全完成的宿主调查。范围包括模型与推理、多模态、工具与计算机/浏览器操作、文件与网络、执行与并发、任务/会话/上下文、后台与计划任务、插件/Skill/MCP/应用、账户/权限/信任、设置/配置/记忆、安装更新恢复、资源和发布分发；发现新类别必须补入。

逐宿主版本、入口和适用账户条件，记录：官方或实际来源、可发现性、读/执行途径、必要权限、调用者、预期结果、失败及恢复者。明确区分未调查、已发现未执行、已执行未核验、已验证、受限、真实不适用。没有接口、缺账户或没有可靠信号不能写成“不适用”来关闭必要缺口；记录具体阻塞、替代路线与剩余义务。

本版在OpenAI范围内按具体执行条件判断候选入口，不默认将ChatGPT或Codex的每个界面列为交付项。CLI是无头环境的一等入口，Desktop的UI能力不能替代CLI；共有实现可以复用，差异和实际效果仍须分别核验。Work和云端保留执行能力依据与待判条件，纯对话仅按实际辅助用途考虑。其它适配保留历史身份并进入后续版本研究，不随3.3分发；未知或受限不等于自动不适用。已纳入目标的宿主功能与设置覆盖要求保持完整。

用户自定义环境是正常使用条件。读取 AGENTS.md 的先后，不等于授权层级或执行优先级；兼容有效配置，并保证必要职责在相关实质动作前参与、动作后获得反馈。开发排除变量优先采用任务级、可回退隔离，随后回到真实自定义环境验证；共享配置调整先明确范围、备份、受影响任务和恢复路径，不擅自扩大信任、数据或费用权限。

资源覆盖包括 CPU/GPU、RAM/VRAM、磁盘 I/O 与空间、进程、终端、浏览器、服务、并发任务和多代理的分配与回收。通过可用的操作系统与宿主原生接口联动观察负载、调整并发、限流、暂停或释放归属清楚的任务资源，再验证负载恢复与必要续做；外围生态能力也要正确发现、启停、复用、回收或退役，不能持续积累。不得盲杀未知进程、关闭防护或重置用户环境；真实不可观测或不可控制项保留具体限制。

既有 resourceStewardship.implementationGate 的接口盘点要求按当前功能切片解释和修订：先查足以决定当前实现的相关原生能力，不把全宿主、全接口盘点设为功能前置。必要缺口可借宿主执行或补充连接闭合，不预先要求 Accord 自建完整操作系统控制器。

## 三组比较起点

1. 当前宿主原生能力：同类任务、相近条件下实际能做什么。
2. 用户实际用过的 前身系统：先定位真实版本、消息触发和接管记录；无法重放时保留历史观察范围，不伪造等条件对照。
3. 不可变 3.2.1 历史包与当前 3.3 开发候选：绑定实际包、模型、入口、工具、配置及任务，区分开发者补救与产品自身作用；当前安装另行核对，不假定它仍为历史包。

没有历史证据不妨碍修复当前已复现缺口；没有因果对照不能声称净收益。替换或删除机制必须保住其仍需结果，减少代码、提示或状态不是独立目标。
