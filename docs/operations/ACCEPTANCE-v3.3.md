八项自举维度按[计划中的映射](PLAN-v3.3.md#自举的能力维度与证据)核对原 A 项，不另建评分或组件要求。工程自举须有自行建立缺失条件后的实际交付证据；认知自述、经验存档和单次改进不代验可靠学习、主观意识或长期收益。

A05择时新增必要反例：下一工作段本身能放下，但会挤占交接、接管验证、失败恢复或安全余量时，不得判为可照常推进；绑定输入、线程/轮次、宿主版本、模型或上下文代次变化以及证据过期必须重评。缺失窗口、占用上界、估计来源、效率范围或继承完整性，不得由累计用量、压缩次数、摘要长度或固定百分比补齐。预算工具输出不授予交接/源释放权，调用者提供的估计不等于原生测量；需另验普通入口自主取数、择时、执行及纠偏。名称统一只支持展示元数据检查，旧缓存界面和真实加载另验。

A05原生观察还须绑定所属连接和具体活动轮次；进入新轮、模型reroute或压缩后重新观察，断连、过期、新未知容量不可保留旧已知值。查询与预算使用之间观察变化时拒绝旧observationId。当前实例的原生动态工具回执与Agent解释只支持显式查询链；若输入点名查询或控制器选择交接时机，不计自主择时通过。通知处理依赖调用者保持真实顺序、完整失效事件及连接归属，助手不能认证外部伪造记录。

恢复输入须区分“旧状态待核对”和“实际输入丢失”：前者不应拒绝正常原生新输入或要求额外私有回放参数，后者保留严格恢复保护。两者均不能自动重新授权旧绑定、解除暂停或覆盖更晚的输入；人工/控制器回放救场不能代验普通输入直连。

连续性对照进一步分开：原生空历史任务从文件接管、Agent自主择时、目标确认/源释放、失败回退与资源收尾分别取证。受控源退出后目标正确续做，只支持相应文件交接路径；控制器发起交接或回收子进程不计自主通过。原生基线没有Accord参与，不能作为当前包或A05整体验收；不要求为已覆盖路径另造状态复制机制。

交接完成必须先于源恢复资源释放，停写不等于释放。目标应按最新目标/授权/关键决策/已发生效果/未完责任核对继承，并明确接受和证明安全接续；缺项、拒绝、陈旧回执、未解决的实质损失或首次接续失败均不放行。已协调的新旧差异与未解决损失分开；提交后的失败先核对目标效果，不能盲目恢复旧写者。交接完成不要求业务目标先全部完成。宿主/模型版本、实际窗口、占用、压缩保真/效率或下一工作段需求发生相关变化时重验就绪状态；未知保持未知，不以固定容量/比例或摘要变短代验。无复制聊天历史也须继承必要任务状态。

ChatGPT入口实验进一步区分：Skill上传、启用、被选中、实际执行与必要原生Hook参与分别取证。临时Chat的个性化/插件状态须回读，启用个性化可能同时引入已有记忆、自定义指令与插件，不能标为干净隔离；不以无插件临时Chat或显式选Skill代验普通入口。独立Skill实验包不属于当前admission已绑定的完整Codex包，局部结果不计作A01–A08通过。预定请求、更正及三文件结果见[工序](PROCEDURE-v3.3.md#chatgpt入口候选准备2026-09-09)。

当前原生普通入口必须核对实际执行环境中的 Node、事件支持、启用状态及当前 Hook 信任，不能沿用旧 Skill 路径的“无前提”声明。未信任时 Skill 可见但入口职责未注入的原生对照，构成安装/可见性不能代验参与的反例；不要求所有后续架构必须使用 Hook，也不授予自动提升信任的权限。桌面打开云任务不等于本地执行，网页安装不部署 Hook 脚本；缺失路径须按原职责研究补位，不以未测或界面控制受限免除必要验收。

## 运行条件与反例

用户操作与环境变化按[节点中的边界](PLAN-v3.3.md#用户操作与环境变化)解释，映射 A01/A02/A03/A04/A06/A08。必要案例同时包含：用户明确切换模式/设置或选用组件；同一操作但未表达其重要后果的意图；无实质任务影响的变化；生效状态不可观测。必要且可观测变化须实际发现，重要且含糊的意图须确认，明确暂停/选择受尊重，确认后完成受影响结果修复和复验。已知选择被强制改回、调用组件被推断为全部追加授权、确认后丢失原责任、未确认按超时继续、无影响仍反复打扰、不可观测被计为全覆盖，均不通过。不能仅以提示 Agent “设置变了”的演示代替自主发现。

开发插件本身、个人指令、记忆、其它 Skill/MCP/App 和系统配置也属于作用条件。配置回读、启用登记、安装字节、当前轮实际采用和行为效果分开取证。隔离需记录实际排除项及残留来源；空配置目录、关闭某一插件或进程返回成功都不能证明初始环境。旧包辅助开发的成果不能自动归因为待测新包；同版本字节漂移也使相关证据失效。完整可用性须回到代表性自定义环境验证，不能强迫用户全局重置。

A02/A03/A06/A08 的代表案例还须包含原先缺少可建立条件的环境：Agent 利用宿主已有获准能力发现缺口、研究替代并建立必要连接，验证生效与后续交付；失败后有仍可工作的恢复执行者，且保留无关配置和用户选择。只在预置齐全的默认环境通过、让用户代建可代办条件、假定最终运行时先存在才能启动、修好启动却没有后续结果，或把未知环境直接排除，均不能完成适应与自举验收。真实不可补足条件需准确说明、可行替代分析及未完责任；不能用越权、无限重试或虚构能力取得通过。

非线性工序同时适用于开发和 Accord 的普通应用，关联 A01/A03/A04/A05/A07/A08。观察依赖独立的工作是否可合理交叉、相关前提变化时是否只重开受影响部分、共享产物是否避免冲突写入；简单任务不被强制拆成复杂流程。授权先于相应动作、接管验证先于源释放等必要局部顺序仍为硬条件。按编号机械串行造成无用等待、并行破坏共享状态、全局重启丢失有效结果，或借“非线性”跳过前提，均为失败。

系统耦合是贯穿实现的必要验收对象：代表性连贯任务须覆盖状态/输入变化对后续执行的影响、连续性与恢复的相互作用，以及交付与资源后态；具体组合按风险预先绑定，不要求穷举所有排列。各项单独成功不能抵消组合失败、共享状态冲突、无存活恢复者或未解决的必要短板。

A06/A07/A08 的生态案例分开核验安装/缓存、上下文暴露、授权/连接及运行资源。按需启用后，在需求结束、依赖变化或异常时调整作用域并核验实际退出；保留明确长期选择与其它任务仍需的共享能力。以已安装数量推定上下文/运行负担、只移除配置便声称释放、无需求仍全局累积、卸载后假称既有上下文已清除或清理误伤共享依赖，均不能通过相关项。沿用事先绑定的资源预算与退出条件，不增加独立生态分数。

A07 操作性说明的关键步骤须由实际产品或可靠操作资料支持；示例和建议与已实现事实区分。关键词、非空文本或产物相互一致不证明可操作性。必要事实缺失时保留依赖待办或提出不可自行取得的必要来源问题，不以一句免责声明同时清空责任、宣称完成。测试提供方也须显式说明来源充分性及不可修改范围，不能用未提供的事实或隐含所有权判据要求 Agent 通过。

已记录未决责任的状态保护与事实发现分开验收：文件谓词全通过也不能消除仍记录的必要条件；恢复/重新绑定省略该字段时不得丢失条件，处置须明确并保持当前输入/授权核对。等待来源不强制重复执行，合法取消仍可退役。声明的理由和字段清空不证明实际事实充分或范围变更合法；接口用例和控制器预绑定不计普通入口自主采用。旧执行者未支持该字段时保护未知，不允许沿用新执行者的通过声明。

A04/A07 的遗留状态案例应预先绑定来源、实际消费者或阻塞效果、必要保留及处置权限，按当前交付是否仍受错误状态影响评定。诊断文件存在不等于仍有活动资源或未完业务；有据保留可以成立，强制删除未知/共享材料不能成为通过捷径。无依据保留且影响尚未核清同样不能宣称闭环；控制器回收整个试验目录不计 Agent 自主处置。前案未满足的删除判据保持原记录，不事后改为通过。

当前v5准入对A08的function范围增加组合约束：至少一个已准入案例在同一episode中覆盖该范围全部职责、质量轴与场景，沿用现有事实各面与episode绑定；不能把不同案例的覆盖并集当完整组合运行。unjoinedCoverage报告此缺项；单项真实通过仍保留。A08.complete同时依赖A01–A07均完成，blockedBy列明未完前提，不以平均分或系统案例单独成功解除。该算法检查证据结构，不认证观察器来源或组合场景充分性，仍需独立复核真实行为与因果关系。

生产级功能以Agent执行入口为关键验收对象；Chat的插件调用、对话及任务衔接独立核验，不排除、不互相代验。目录上架是分发事实，不是调用能力判据；对未上架组件分别观察受支持的侧载、加载和执行路径。

有效工程原则适用于各类Agent任务，内化实现与复用宿主能力均按同一职责的实际结果验收，领域正确性另有对应检验。原生处理足够的场景允许不调用额外机制；原生处理不足的风险场景必须验证必要保护与恢复。2026-09-09无预置状态的同轮更正仅提供前者的有界证据，不能由此删除后者，也不能用控制器替Agent绑定后证明自主选择。验证器修复后的旧日志复核与新原生运行分开，原判定及变更来源保留。

持久化分层取证：退出后状态保存、同目标跨任务关联、恢复后效果核对与续做、无提醒再次唤醒各自需要证据。稳定目录与文件刷新不自动证明断电安全；同session/cwd的子进程终止测试不代验Agent新任务接管。新旧状态冲突必须保留并停止依赖动作，不能按时间戳擅自合并；暂停、取消和权限撤回不因恢复而失效。历史canContinue不是当前授权，宿主调用成功也不是主体控制权已经保全的证明。

“按需适时自主调用”适用于A01–A08相关全部能力，不只fork：在用户仅描述业务目标、没有点名工具的条件下，提供真实调用机会，观察Agent是否发现需要、选择时机、执行、处理反馈或失败、继续任务并收尾；同时提供无需求或条件不足的反例，检查是否避免无益调用、虚假成功或越权。独立记录必要但未调用、调用过早或过晚、无需求却调用、调用后无人接续。只证明API可调用、用户命令后执行或一项fork成功，均不能代表全能力自主闭环。无需机械穷举一切工具，但每项必要职责必须有对应场景和当前证据。

对课程、教程、Skills 等外部方法，核对当前官方支持边界、来源与时效、适用条件以及可复现效果；允许有证据支持的第三方更佳路线。失败包括：把价格/热度/作者身份或“官方推荐”当成效果证明，把筛选与技术学习交还用户，或只给资料清单而未完成可代办工作。用户保留关键决定，Agent 说明足以影响决定的依据与不确定性。

模型适配需覆盖目录更名/增删、账号缺少某选项、当前派发接口不支持目录中的模型、推理选项改变、权限或额度错误以及用户排除项。观察动态候选重算、授权内替代与实际执行；不能用静态型号表、当前 Pro 账号成功或仅查询目录代验非 Pro 与跨入口可用性。一次模型名和推理强度只绑定该次证据，不升级为通用最低档。本轮不调用 Spark。
