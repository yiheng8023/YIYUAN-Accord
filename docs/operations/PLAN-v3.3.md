# 3.3 计划：功能优先，恢复自动化与协作内核

修订：r2 · 2026-09-09。当前阶段：已授权交接并进入功能开发；本次修订尚未实现 3.3 产品功能，验收条目仍待验证。

本文件是 3.3 当前计划入口，与 [基线](BASELINE-v3.3.md)、[工序](PROCEDURE-v3.3.md)、[验收](ACCEPTANCE-v3.3.md)共同使用。3.2.1 的冻结开发定义与旧计划保留其历史范围，不能成为 3.3 当前进度，也不因本规划改写已发布结果。

## 核心交付

基于 3.2.1 持续打磨、强化内核，找回并兑现原定的高度自动化：用户表达意图并作关键决策，Agent 借助宿主与生态主动完成必要发现、执行、纠偏、恢复、验证和收尾。自动化弱化是原有职责的回归问题，不作为新卖点凑版本。全链路协同、独立主权、不盲目扩张、历史债务肃清及系统平衡继续保留。

首阶段只适配 ChatGPT/Codex，分别核实 ChatGPT 各实际入口与 Codex Desktop、CLI 等入口的能力、接入和调用条件。Claude 及其它宿主的 3.3 适配暂缓，待本阶段跑通后再考虑；保留已有历史包与证据。本范围适用于下列全部 F/W/S/A，不能借一个入口成功宣称另一入口可用，也不能悄悄把 ChatGPT/Codex 缩成仅 Codex。

不预先指定只用 Skill、必须无运行时、必须自建运行时或统一控制面。由实际缺口决定组件组合；原生优先是合理起点，不是拒绝更合适工具的理由。替代实现必须履行同一职责，不能把缺口留给用户。

保留历史中仍有效的结果和机制，3.3 不整体推倒重来。信息不确定或时效性重要时，W02 主动联网核对官方或其它可靠资料；涉及可复用实现、生态方案且有改善任务路线的实质可能时，搜索 GitHub 等来源的成熟实现，有界比较适配、效果、维护、许可和授权后再行动，即使原生已能完成也一样。复用可靠研究，停止不能改变选择的搜索；不把调研变成无期限前置。

实现目标是“除必要人工介入外的高度自动化”。接受为有效自动化承担合理的运行和维护成本，不要求每个必要连接先证明省 Token 才准实现。优先顺序为：守住真实授权与输入保护，打通必要自动化并达到结果质量，再优化同等效果下的无效开销。不能把功能缺失和低成本当作可互相抵消的权衡。

### 自动化如何落地

W02/W03/W05/W06 联合对每个必要职责接通以下路径，具体组件按宿主条件选择：

1. **触发**：从普通输入、工具完成/失败、等待结果、需求或环境变化、上下文事件等实际入口发现需要。必要任务入口参与必须有可靠连接，不能只依赖偶尔选中 Skill；若任务要求无人值守后续动作，落实能再次唤起执行的宿主调度或必要替代，不能依靠用户再发一句“继续”。
2. **判断与执行**：AI 宿主中的 Agent 解释当前目标和授权、选路并调用适用能力；Accord 接通职责而不重建一套智能判断系统，确定性条件可由代码检查。Skill 按需支撑判断，不单独承担强制触发或后台执行保证；逻辑协作不要求所有工具经过 Accord 代理。
3. **状态**：为跨轮、重启、交接和失败恢复保留必要的当前目标、未完工作、授权范围、输入新鲜度及已完成效果；状态写入本身不算工作完成。
4. **恢复与再执行**：明确失败后仍存活的执行者、重新进入条件和重复执行保护。宿主能可靠续做则直接使用；不能时补必要的持久机制，不能把“当前轮已结束”当作未完工作的终点。
5. **验证和收尾**：依据实际结果继续、纠正或完成；清理任务资源并保留必要后态。真正缺少目标决定、新授权或本人动作时，才把具体选择交给用户。

不能以完成上述设计表代替接通路径。每个实现切片都要观察真实触发、动作、失败及恢复；需要持久运行时、状态或调度连接时，应实现相应能力，不把“轻量”当架构禁令。后台监听或轮询也不是越多越好，以可用唤醒和完成结果为准。

W02 由 Agent 主动发现宿主相关功能、按钮、设置、配置与生态，使用实际接口、UI 或官方来源验证可见性、可调用性与授权；不要求先建全量静态能力库。W01/W06 协同用户自定义配置：AGENTS.md 读取顺序不等于授权层级或执行优先级，必要职责在相关动作前参与并获得动作反馈。排除开发变量时优先任务级可回退隔离，再在真实自定义环境复验；共享改动明确范围、备份与恢复，真实新增信任、数据和费用仍依授权。

W02/W06/W07 联动操作系统与宿主运行态，覆盖 CPU/GPU、RAM/VRAM、磁盘 I/O 与空间，以及进程、终端、浏览器、服务、并发任务、多代理的分配与回收。通过实际可用原生控制按负载调整并发、限流、暂停、恢复或释放明确归属的资源，验证负载恢复、必要工作继续和退出后回收。外围生态能力按任务正确启停、复用与退役，不能只增不退。资源管理不能缩成删临时文件；不盲杀未知进程、关闭防护或重置用户环境。代表性持续运行、压力和退出残留条件纳入 S3/S4 与 A06/A07/A08，不等最终发布才发现累积问题。

以上承接既有 resourceStewardship 职责，补实际闭环证据与已证实断点。其历史接口盘点前置随本轮功能优先原则纠正：只先查当前切片决策相关能力，不等所有宿主接口穷尽后才补必要机制；不因缺少独立资源执行器就断言宿主无法承担。

## 排程与首个实施切片

S0 只解决会影响第一项实际工作的必要事实，不先做全量历史治理或所有宿主调查。首个切片从本阶段 ChatGPT/Codex 范围内实际可执行的普通入口任务开始：给出目标及既有授权，核对必要入口职责是否真实参与，途中出现可识别工具失败与需求变化，观察 Agent 是否自行调整、修正已有产物、核验交付并收尾。优先覆盖 F01–F04、F07；宿主发现 F02 按该任务直接接入。先复现和修复，再扩展本阶段其它失败条件与入口。

F05 的自然长任务观察与必要受控验证分别记录；不能等待自然压力出现才推进其它功能，也不能在用户提示后演示交接冒充自主触发。F06 的实际配置/生命周期依赖只在相关切片中核对。完整宿主覆盖仍是 W02 的持续交付，不随首个切片结束而关闭。

修复可跨工作包，工序可交错。每次选下一步，以能兑现必要结果、减少最大阻塞或最高用户负担为依据；不为遵守编号机械串行。稳定功能形成后开展 S4 的系统对照；关键授权与数据保护无需等到 S4。

## 原草案继承与勘误

原传播工作目录中的《Accord-3.3-计划草案》《3.3规划摘要》作为历史提案，当前规划以本组文件为准。原六个内核工作包及分发准备的内容映射如下，防止改版丢项：

| 原工作包 | 本次承接 |
|---|---|
| 1 当前事实/唯一入口 | W01 与 S0；历史治理不再作为全部功能的长前置 |
| 2 缺陷债务/脱敏反馈 | W03/W04/W06/W07；缺口包括尚未实现的原定职责，不限于已能局部复现的旧 bug |
| 3 宿主能力/加载/质量路线 | W02/W06；从有限入口清单扩为全能力覆盖责任 |
| 4 意图、纠偏、恢复、连续性 | W01/W03/W04/W05/W07；自主触发与辅助完成分开验收 |
| 5 证据/评审/维护成本 | W07/W08；保留有效控制，删除重复控制须验证效果不丢失 |
| 6 系统平衡/陌生用户入口 | W08；陌生用户招募与私有数据访问另按实际授权，普通无提示条件先明确 |
| 7 公开市场分发 | W08/S5；GitHub 唯一首发，市场用于发现安装，不能为上架删掉必要功能 |

公开市场的当前提交条件、宿主功能差异、是否需要合作在准备提交时重新核实官方来源，不沿用旧网页结论作为当前事实。身份核验、申请、外联和公开发布按届时授权进行；外部审核不阻塞内核功能工作。

## 动态校准

新用户纠正、复现失败、能力或宿主漂移、历史成功链路发现、负担上升、验收反例均可触发修订；不等节点或最后交付。每次记录改变的事实、受影响 F/W/S/A 编号、实际纠正动作和仍未解决项。更新关联文件与原生 update plan，保留原验收结果的版本和失败身份。

方法、工序顺序、局部预算与合理阈值可随证据调整；改变用户结果、缩小必要覆盖或新增外部影响不能靠编辑计划暗中获得授权。真实受限的必要能力仍为受限/未完成，不能改名“不适用”算通过。不承诺全局最优，要求说明当前选择相对可行替代的理由。
