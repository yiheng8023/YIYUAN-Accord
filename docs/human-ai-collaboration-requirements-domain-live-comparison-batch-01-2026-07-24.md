# Requirements And Domain Weak-Agent Live Comparison — Batch 01

## Scope

This batch executes the pre-registered `SE-DISCOVERY-REQ-01` synthetic
requirements/domain challenge. It compares a Spark/low native baseline with all
configurable user Skills disabled against the same host/model with only the
CC Switch-managed `grill-with-docs` Skill selected.

All six runs used disposable roots, approval `never`, no network, no external
write, and stable global configuration. Nine earlier environment or
measurement-invalid runs remain recorded by the parent protocol and do not
count in this aggregate.

## Observed result

Three valid pairs completed. Visible tests passed native 0/3 versus candidate
1/3. The independent hidden contract passed native 0/3 versus candidate 0/3.
Across the three runs, the native arm produced 22 hidden failure-code
occurrences and the candidate arm produced 24.

Both arms missed the canonical-term and Customer/User distinction checks in
all three repetitions. Each arm produced one run with forbidden status
promotions. The candidate arm reduced the failure count in pair 1, expanded it
sharply in pair 2, and passed only the visible surface in pair 3 while still
missing six hidden source and domain checks.

The candidate therefore does not demonstrate added value on the hard contract.
The mixed visible result also does not establish native superiority, candidate
harm, or Skill causation. Exact selected exposure and structured Skill input
acceptance were observed; no independent loader event or proof that the exact
candidate instructions reached the model exists.

## Decision

Stop identical requirements/domain repetitions. A fourth run on the same
fixture would add little decision value. The next comparison must use a
materially different discovery or requirements scenario and preserve the same
hard standards.

This is not evidence that every Skill harms performance. It does not justify
installing, removing, replacing, or rewriting a Skill; it does not prove a
self-authored residual gap; and it does not validate product discovery,
complete requirements, implementation authority, or cross-host behavior.
