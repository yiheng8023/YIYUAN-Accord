## 2026-07-28 Skill-portfolio execution recalibration

The next Skill-portfolio phase is subtraction-first and manager-backed. The
dated live counts are inventory observations, not progress or quality targets.
CC Switch remains the operational manager for shared third-party Skill source,
installation, update, supported-consumer projection, backup, and restore. A
candidate's own one-click installer must not create a second unmanaged
installation path when CC Switch is the selected manager. CC Switch repository
metadata is a discovery and transaction surface, not source-freshness
authority: every selected source or component is reconciled against its exact
upstream revision and current dependency set before reliance.

Retain `~/.agents/skills` as the common compatibility root even when a
particular cleanup leaves it empty or links-only. Future Agents may
legitimately use that root, so root existence is a compatibility invariant
rather than proof that it owns every contained Skill. Govern physical bodies,
managed links, source authority, and consumer need item by item without
clearing the root itself. Codex and Claude are distinct hosts; their effective
Skill packages may differ where the host contract requires it, so cross-host
byte equality is not an acceptance criterion.

Preserve foreign lifecycle boundaries before changing the shared portfolio.
Trae owns its physical `~/.trae-cn/skills` root and the versioned Skills inside
its Feishu Plugin. The current Trae shared root contains no Lark Skills and no
CC Switch links; the Plugin retains its own 26-item Lark dependency set.
Neither root is a CC Switch consumer or cleanup target. The separately observed
27-item CC/common Lark cohort was later removed as one dependency-aware
shared-portfolio transaction through CC Switch, with the independent
schema-3-locked `.agents` copies removed atomically and Trae's two foreign roots
unchanged. The dated
[removal event](CC-SWITCH-LARK-COHORT-REMOVAL-EVENT-2026-07-28.md) records the
pre/post manager, projection, foreign-sentinel, sync, backup, and cleanup
evidence. This subtraction does not prove loader behavior, portfolio quality,
or program closeout.

Use this execution order:

1. inventory every relevant carrier by owner, source, exact revision,
   dependency closure, physical or linked state, consumer, and loader surface;
2. remove unneeded, broken, stale, duplicated, or account-bound shared
   capability only through a previewable, backed-up, reversible manager
   transaction, while preserving foreign-managed roots;
3. reconcile CC Switch snapshots with exact upstream source truth and treat
   stale catalog rows, retired upstream entries, renamed components, and
   dependency drift as lifecycle events rather than quality failures;
4. deduplicate by capability, authority, dependency, invocation, and verified
   behavior rather than directory name or body hash alone;
5. survey native/runtime, official, reviewed maintained external, and composed
   paths using CC sources, the user's public candidate lists, prior governed
   discovery, and materially relevant sources beyond those lists; do not
   optimize for installed count or install a whole source merely because it is
   indexed;
6. treat `intent-contract`, `capability-router`, and `closure-contract` as
   falsifiable upstream candidates and phase controls, not presumed permanent
   answers or presumed waste. Review their global `AGENTS.md`, Skill, reference,
   Hook, loader, compression, handoff, branch/worktree, MCP, and failure-fallback
   relationships as one governed chain. Narrower third-party superiority does
   not by itself disprove the broader `capability-router` role or authorize
   wholesale retirement. A current turn that appears to select a Skill
   implicitly is only an observed behavior: native/runtime discovery, global
   rules, the self-authored Skill chain, Hook recall, and their composition are
   competing causes until a controlled ablation separates them. The
   2026-07-29 current-host sentinel ablation now proves that Codex `0.145.0`
   independently supports description-matched implicit Skill selection and
   full `SKILL.md` reading when global instructions, the three self-authored
   Skills, the Codex-private Skill root, and Hooks are excluded. This proves
   native capability existence, not that native behavior caused an earlier
   mixed-carrier turn or that the self-authored chain has zero incremental
   value;
7. author, retain, adapt, compose, or retire local controls only after a
   repeatable residual gap or redundancy survives the earlier steps and the
   affected instruction, Skill, Hook, consumer, backup, rollback, and handoff
   carriers have one explicit migration disposition.
