the 2026-07-18 program-level gap review. This reconciliation binds those dated
records back to program acceptance without promoting any capability claim.

- `acceptance.dynamic-runtime-control-gap-research`;
- `acceptance.native-task-orchestration-boundary`; and

`acceptance.end-to-end-process-fidelity`, and binds the observer-acquisition

`acceptance.dynamic-runtime-control-gap-research`. Both target criteria remain

reconciliation includes those named live host observations rather than

## MCP lifecycle

The repository now binds the Codex app-server `0.145.0` direct-call,
startup-profile, new-thread reload, idle-unload, child-exit,
reload-release-attribution, paired thread-unsubscribe, and multi-connection
preflight observations, plus the unexecuted creator-connection-close protocol,
one invalid pre-window calibration attempt, the observer-acquisition admission
gate, the auto-attach v2 offline amendment and protocol, and offline
task-selection, lifecycle, skeleton, and same-thread refresh contracts.

In three independently isolated five-second repetitions, disable plus reload
did not release the already-loaded Sentinel: all 33 exact process samples
matched, no stop event occurred, and the original thread returned the same PID
and instance after the window. The status projection exposed no callable tools,
so status/runtime divergence was reproduced. This falsifies reload as an
observed immediate-release mechanism for that Sentinel, host, version, and
window.

In three additional concurrent paired repetitions, each unsubscribe arm sent
only `thread/unsubscribe` while its independently hosted subscribed control
sent no request. All three unsubscribe responses were `unsubscribed`; all 66
samples across six independent runtimes retained the exact identities, no stop
event occurred, and all post-window calls returned the original PID and
instance. This falsifies unsubscribe as an observed immediate-release
mechanism only for those Sentinels, host, version, and five-second windows.

The three-run multi-connection preflight kept one app-server and two
independent loopback WebSockets per repetition. Both connections called the
same exact Sentinel, but the second returned `notSubscribed` twice in every
formal repetition. Callability therefore did not satisfy the required second
independently releasable subscription, and the final-owner branch remains
stopped.

The follow-up observer-acquisition gate machine-checks those three reports and
admits only an offline amendment: the reproducible acquisition path is
`thread-created-auto-attach`, while the historical protocol/probe still depend
on `thread/resume`. Auto-attach callability is not admitted as a second
subscription or independent owner, and the gate authorizes no live rerun.

The v2 amendment preserves the historical protocol and probe, initializes
connection B before creator connection A starts the thread, performs B's
post-start observation by direct call without `thread/resume`, and treats
rollout materialization as diagnostic only. Its 16 scenarios use injected

`MCP-THREAD-CREATOR-CONNECTION-CLOSE-ATTRIBUTION-01` is the next narrower,

## Program decision

The current gap is no longer “collect any more Context/Git/MCP evidence.”
Future work must target one named live gap with a compatible host, authority
boundary, oracle, rollback, and claim limit.

The current evidence does not justify a self-authored runtime controller.
Native/runtime and CC Switch responsibilities remain preferred, and a new
offline simulator is not the next default step.
