# Human-AI Collaboration Access And Communications Capability Baseline

Date: 2026-07-31
Status: source-bound static capability baseline; no live translation,
accessibility-conformance, recipient-understanding, admission, or standards evidence

## Decision

For `GEN-ACCESS-COMMS-01`, the smallest representative route is an ordered
composition rather than one universal Skill:

1. lock the source message, terminology, obligations, uncertainty, actor,
   deadline, units, and intended recipients;
2. use native capability for the draft semantic and language adaptation;
3. reuse the frozen nine-case structured semantic-loss gate;
4. add OpenAI Documents only when a DOCX carrier or its narrow structural
   accessibility checks are relevant;
5. require bilingual, domain, accessibility, and recipient review in
   proportion to consequence, with release authority retained by an authorized
   human or accountable organization.

No current source establishes a portable universal Skill for consequential
multilingual adaptation, accessibility conformance, and recipient
comprehension. The remaining gap is behavioral and recipient-evidence work,
not a reason to author another Skill or accumulate more candidate names.

## Stable neutrality boundary

Project neutrality has not changed. Native, official, external, installed,
popular, self-authored, and familiar routes receive no automatic evidentiary
authority. Human language, domain, accessibility, and recipient judgments are
legitimate inputs with identified owners and review surfaces; they must not be
silently generalized into universal facts.

## Reused deterministic gate

The existing zero-model protocol and fixture are reused, not duplicated. Their
control plus eight faults cover obligation weakening, actor swap, negation
flip, deadline and unit drift, uncertainty deletion, invented commitment,
terminology drift, and accessibility-structure break. The evaluator recomputes
loss from the parent source and preserves cumulative historical loss after
terminal recovery.

This gate evaluates structured semantic normal form only. It does not prove
free-form translation, bilingual or domain correctness, accessibility
conformance, recipient comprehension, human-review effect, candidate value, or
cross-host behavior. `GEN-ACCESS-COMMS-01` therefore remains
`planned-no-live-domain-evidence`.

## Candidate boundaries

OpenAI Documents `26.730.11710` is a downstream carrier and document-quality
capability. Its accessibility task checks headings, image alternative text,
table header flags, and descriptive links, and explicitly says it is not a
full WCAG engine. It does not supply semantic translation, terminology lock,
recipient comprehension, or release authority. Google Docs import also crosses
a separate Google Drive account boundary and is unnecessary here.

The installed `edit-article` Skill is excluded as a treatment. It improves
article clarity and flow but lacks translation, obligation and uncertainty
fidelity, terminology control, accessibility verification, bilingual review,
and recipient testing. Its prior native-overlap rejection and subtraction
disposition remain unchanged; this baseline authorizes no removal.

Microsoft's official Azure Translation SDK Skill is a real external discovery,
but it teaches an Agent to build against an Azure service. It requires a
package, endpoint, credential or key, network, and service/account boundary. It
can be reconsidered for a recurring translation application, not used as the
default route for this one synthetic consequential-message comparison.

Weblate glossary checks and Translate Toolkit `pofilter` are mature
localization-workflow references for terminology and file-based QA. W3C WAI
guidance is an accessibility reference. None is a current universal Agent Skill
or proof of combined semantic fidelity, accessibility, and recipient
understanding.

## Next evidence gate

A later, separately authorized comparison should use the same source and
terminology lock across native and any eligible candidate arm, run the existing
deterministic gate first, then obtain bilingual/domain review, accessibility
checks appropriate to the carrier, and a recipient comprehension sample. A
human-only control remains required.

Improved fluency is not semantic fidelity. Readability or structural checks are
not accessibility conformance. Machine translation is not certified
translation. Recipient understanding cannot be claimed without recipient
evidence.

## Explicit non-authorizations

This baseline authorizes no model dispatch, candidate or service execution,
package installation, account connection, translation upload, CC Switch,
Plugin, MCP, runtime, Skill, Hook, standards, cross-repository, Git commit, or
remote-push mutation. It creates no acceptance criterion and changes no
existing acceptance assessment.
