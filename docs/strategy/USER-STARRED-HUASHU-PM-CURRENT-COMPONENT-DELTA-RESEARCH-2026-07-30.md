### Bound component decision: no current atomic candidate

The Round 02 review separated:

- design-direction and anti-generic guidance;
- brand-asset provenance;
- HTML/PDF/PPTX/video export;
- TTS and cloud media;
- bundled assets.

That separation remains correct, but the current upstream distribution does
not expose the first two as independent Skills. The single root `SKILL.md`
routes into the references, assets, scripts, demos, gate files, and optional
Hook. The README explicitly warns that installing only `SKILL.md` is
dependency-incomplete. Selecting the root body would therefore select much
more than the creative-direction question bound by `GEN-CREATIVE-01`.

For this scenario, the likely marginal ideas are:

- showing materially different visual directions before convergence;
- recording assumptions and the user's chosen direction;
- using real, permitted brand/design context rather than guessing;
- separating critique from the creator's final aesthetic choice.

However, the current host already exposes OpenAI-official:

- Creative Production `produce`, which defaults to 4–6 distinct visual
  directions, preserves hard constraints, avoids invented claims, and keeps
  selection/refinement with the human;
- Product Design `ideate`, which generates three independent directions,
  requires direct inspection of references, preserves source context, and
  stops for human selection before build;
- Product Design `audit`, plus native ImageGen, Figma, presentation, browser,
  and review surfaces for later task-specific use.

The installed CC portfolio also has design/prototype/review bodies, although
the current subtractive triage already treats `design-an-interface` as a
removal-preview candidate and its software-interface focus is not a creative
production substitute. Static availability is not behavioral equivalence, but
it is enough to block a claim that Huashu's three-direction workflow fills an
unoccupied atomic slot.

Therefore:

```text
GEN-CREATIVE-01 × current Huashu
-> no current atomic candidate
-> retain source metadata and current pin
-> reopen only after a fixed comparative brief proves an unmet marginal need
```

This is not a rejection of the source. It avoids treating a broad, tightly
coupled production system as a small creativity-control primitive.

### Dependency, permission, and portability boundary

The current source declares:

- npm dependencies on `playwright`, `sharp`, `pptxgenjs`, and `pdf-lib`;
- local `ffmpeg`/`ffprobe`/browser/media subprocess expectations;
- optional network reads for public images, brand assets, fonts, and CDNs;
- optional ByteDance/Volcengine TTS and AI video review using user-supplied
  credentials and explicit source-side consent flags;
- project-local output and gate-file writes;
- an optional PreToolUse Hook that can block qualifying render commands;
- one optional HyperFrames path that can install additional Skills.

The source's `SECURITY.md` is useful declared behavior, not independent
execution evidence. MIT applies to repository software; it does not by itself
prove asset-level provenance, third-party brand permission, generated-output
rights, API authorization, or safe behavior of every dependency.

The README describes cross-Agent compatibility and the Skill uses relative
paths, but the full workflow assumes host-dependent subagents, file writes,
shell tools, browser automation, Hook semantics, context capacity, and
optional cloud credentials. Its weak-runtime branch is an upstream adaptation
claim, not current Codex, Claude, opaque-host, or cross-host behavioral proof.

- incentives and distributional impact;
- low-power affected-subject protection;
- explicit decision and consultation authority;
- reversible option design and rollback;

official data-analysis, and repository governance surfaces overlap
