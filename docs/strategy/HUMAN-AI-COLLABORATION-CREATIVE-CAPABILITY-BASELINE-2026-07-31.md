# Human-AI Collaboration Creative Capability Baseline

Date: 2026-07-31
Status: source-bound static capability baseline; no live creative, rights,
candidate-admission, Skill-authoring, or standards evidence

## Decision

For `GEN-CREATIVE-01`, the representative set is sufficient for the next
evidence gate:

1. native open divergence without a dedicated creative capability;
2. OpenAI Creative Production `0.1.25` inside its host-specific board and MCP
   boundary;
3. Matt Pocock's `grilling` only as an explicit and proportional precursor
   when consequential brief decisions are genuinely missing;
4. human-led ideation as the control and authority-retaining fallback.

Broader discovery stops for this slice. This does not establish ecosystem
completeness or candidate superiority. The residual uncertainty is a
behavior-, rights-, and edit-burden evidence gap, not a capability-name gap.

## Stable neutrality boundary

Project neutrality has not changed. Native, official, popular, installed,
self-authored, and familiar routes receive no automatic priority beyond the
general least-cost and trust tie-breakers. Each route must still fit the bound
scenario and evidence surface.

Aesthetic and value judgments are not defects to remove. They must retain an
identified human owner, context, uncertainty, and review method, and must not
be silently generalized into objective or universal facts. Final aesthetic
choice stays with the human. Rights and publication decisions stay with an
authorized human or accountable organization.

## Scenario and reused deterministic gate

The task is to create several materially different directions from an
incomplete brief while preserving intent and rights. Draft and critique are in
scope. Publication, purchase, rights transfer, and destructive asset edits
need separate authority. Inputs are limited to the user brief and licensed or
explicitly permitted references.

The existing six-example Unknown Knowns creative preference packet is reused,
not duplicated. It already fails closed on brief-fact loss, converged primary
axes, hidden preference promotion, generation-only rights clearance, and
unauthorized publication. It is a deterministic output gate, not evidence
that any candidate was invoked or produced valuable creative work.

`GEN-CREATIVE-01` therefore remains `planned-no-live-domain-evidence`.

## Candidate boundaries

OpenAI Creative Production is a current official visual-production candidate,
not a portable generic creative Skill. Its package declares interactive and
write capability, a bundled Node MCP server, an empty direct App declaration,
implicit invocation metadata for `intake` and `produce`, board-first work, and
four to six directions by default when appropriate. Its source-preservation
and exact-content contracts are relevant to intent fidelity, but static bodies
do not prove current MCP health, board availability, instruction delivery,
rights traceability, or creative value.

`grilling` supplies one-question-at-a-time decision clarification and keeps
decisions with the human. It is not the default creative route. Use it only
when consequential decisions are actually missing and the user explicitly
wants deep stress-testing. Intentionally unresolved aesthetic preferences must
remain open inputs to divergent exploration, not be forced closed as intake
defects.

Superpowers `brainstorming` is excluded as a `GEN-CREATIVE-01` treatment. It is
a software-development methodology with mandatory project context, design
approval, specification, review, and implementation planning. Its useful
multi-option idea remains software-method reference material, but the complete
workflow would add unrelated ceremony and writes here.

Current Huashu remains a broad root suite with a media and design dependency
tree, direction gates, and an optional blocking Hook. The prior exact-source
review found no independently attributable lower-cost component for this
scenario. It therefore supplies no current install or execution candidate.

## Next evidence gate

Any later candidate output must first pass the existing deterministic packet.
A separately authorized live phase must then prove exact host exposure and
instruction delivery, preserve a revision and rights/provenance log, compare
against native and human-only controls, and use blind human review for
directional diversity, intent fidelity, and correction or selection burden.

Direction count is not creative diversity. Generation is not rights
clearance. One reviewer's preference is not universal aesthetic quality.

## Explicit non-authorizations

This package authorizes no model dispatch, board or asset write, plugin or MCP
execution, installation, account connection, CC Switch or runtime mutation,
Skill or Hook authoring, hard-standard promotion, cross-repository write, or
remote push. It creates no new acceptance criterion and changes no existing
acceptance assessment.
