# Human-AI Collaboration Learning Capability Baseline

Date: 2026-07-31
Status: source-bound static capability baseline; no live learning, candidate-admission, Skill-authoring, or standards evidence

## Decision

For `GEN-LEARNING-01`, the current representative set is sufficient to design
the next comparison protocol:

1. native Agent behavior without a dedicated learning capability;
2. one official host-specific learning mode within its own account and product
   boundary;
3. Matt Pocock's `teach` Skill as an explicit, task-bound external treatment;
4. an accountable human instructor or mentor control.

Broader third-party discovery stops here for now. This is not a claim that the
ecosystem is complete or that these candidates are best. It means the current
blocking uncertainty is a behavioral-evidence gap, not a capability-name gap.
More candidate names would not establish durable learning, transfer, learner
autonomy, accessibility, or acceptable lifecycle cost.

## Scenario and evidence boundary

The bound task is tutoring through explanation, retrieval, practice, and
feedback while measuring durable competence rather than answer completion.
Practice support is allowed. Grading, certification, accommodations, and
high-stakes progression remain with accountable educators. Only the minimum
learner profile and task history belong in the trial.

The evidence state remains `planned-no-live-domain-evidence`. A useful protocol
must include a pretest, delayed unaided post-test, novel transfer task,
misconception oracle, teacher review, human-only control, learner-autonomy and
accessibility observations, and lifecycle-cost accounting. Static metadata,
installed state, or immediate task completion cannot promote that state.

The Shen and Tamkin study is a bounded design input: it supports separating
task correctness and completion time from independent human competence. Its
one-session unfamiliar-library result does not establish universal or
long-term learning effects and does not compare the candidate routes here.

## Official surfaces

OpenAI documents ChatGPT Study mode as a Socratic and stepwise learning surface
with open-ended checks, quizzes, file support, and optional memory. Anthropic
describes a Claude education learning mode focused on tutor-like questioning
and transferable thinking. Google documents Gemini Guided Learning with guided
questions, multimodal explanation, practice, feedback, and hints.

These are useful official reference routes, but each is host-, account-, and
product-bound. They are not one portable Skill, are not proof of current
account availability, and do not establish delayed retention, novel transfer,
or cross-Agent behavior. A future trial must select one surface explicitly and
retain its data and account boundary; the three products must not be merged
into a fictional cross-host treatment.

## Matt `teach` boundary

The observed `mattpocock/skills` `main` commit is
`2ab958093e83e0ec752e6c1c5932da465bf23e0c`. The exact six-file local `teach`
projection is recorded in the registry baseline. CC Switch is the physical
authority root, with symbolic-link projections into the shared Agents, Claude,
and Codex roots. OpenAI metadata requires explicit invocation.

`teach` has a credible differentiated role when learning needs a durable,
multi-session workspace: mission and source grounding, retrieval, spacing,
interleaving, learning records, feedback loops, and reusable lesson artifacts.
Its costs are equally material: many workspace writes, HTML or asset artifacts,
more context and cleanup burden, and possible research or command surfaces that
need separate authority. Projection proves neither instruction delivery nor
learning value.

Therefore `teach` stays installed but task-bound and explicit. This baseline
neither admits it as a generally preferred route nor supplies a reason to
remove it.

## Route comparison

| Route | Distinct value | Principal open evidence |
| --- | --- | --- |
| Native / no dedicated capability | Lowest structure and lifecycle cost | No durable workflow or competence measurement guarantee |
| Official host learning mode | Guided or Socratic interaction with low integration cost inside one host | Current account availability, delayed retention, transfer, portability |
| Matt `teach` explicit treatment | Durable learning workspace and multi-session artifacts | Instruction delivery, causal behavior, retention, transfer, mutation and cleanup cost |
| Human instructor control | Accountable judgment, accommodations, high-stakes authority, fallback | Availability, consistency, time and coordination cost |

The comparison does not rank the routes. It identifies why each must remain
distinct and which evidence can falsify its use.

## Stop conditions and next gate

Discovery remains stopped until one of these triggers appears:

- a bound learning task falls outside the representative coverage;
- an official surface or Matt `teach` materially changes;
- a route fails health or exposure preflight;
- a fixed protocol exposes a specific missing capability rather than missing
  evidence;
- account, data, accessibility, language, host, or authority boundaries change.

The next bounded action is protocol design, not another catalog sweep and not
Skill authoring. The protocol must be fixed-fixture, no-install, and
no-account-expansion by default. Simulation comes first. Manual or real-learner
testing is reserved for effects that deterministic checks cannot establish.

## Explicit non-authorizations

This package does not authorize candidate execution, model dispatch,
installation, account connection, CC Switch or runtime mutation, Skill or Hook
authoring, hard-standard promotion, cross-repository writes, or remote push.
It creates no new acceptance criterion and does not change any existing
acceptance assessment.
