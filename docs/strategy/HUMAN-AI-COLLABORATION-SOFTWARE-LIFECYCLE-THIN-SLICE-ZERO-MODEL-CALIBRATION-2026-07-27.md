# Source-backed software lifecycle thin-slice: zero-model calibration

Date: 2026-07-27
Scenario: `SE-E2E-THIN-01`
Status: `valid-calibration-only`

This calibration introduces no new Manager or Skill. It composes existing
requirements, TDD, process-fidelity, read-only Git observation, rollback,
incident, and maintenance semantics behind a new seven-stage evidence
envelope. The frozen three-stage/five-edge process-fidelity trace remains
unchanged.

The seven material stages are requirements/domain, architecture, bounded
implementation/TDD, independent review/test/security, simulated
release/rollback, simulated observation/incident handling, and maintenance.
G0–G7 are separate, single-use authority receipts. Earlier approval never
authorizes a later truth change or side effect. Only the frozen source or one
exact current human receipt may change the cumulative accepted invariant
ledger; Agent output can propose a change but cannot promote it.

The persisted capture was reopened from raw bytes. Raw and canonical hashes,
multi-input predecessor links, stage definition hashes, receipt self-hashes,
ledger continuity, append-only transition history, exact claim boundaries,
and stage-specific falsifiers were recomputed by the parent evaluator. The
positive path reuses the TDD timeline oracle, lifecycle release/rollback
policy oracle, disposable incident/migration runner contract classifier, and
deduplicated cumulative-loss ledger. It now also executes the incident and
migration packets in disposable directories. Exact focused-test identities,
expected-behavior assertion failures, implementation hashes before RED,
S0–S3 stage receipts, allowed mutation sets, focused GREEN, and the existing
private final oracles are parent-recorded and hash-bound.

Architecture and independent review/security now have a small deterministic
calibration adapter. Architecture controls bind requirements, sources,
constraints, domain terms, alternatives and trade-offs, dependency direction,
quality-attribute scenarios, failure modes, real versus hypothetical seams,
open unknowns, migration impact, rollback, and authority claims. Security
controls use three predeclared faults, two benign canaries, exact locators,
severity floors, supply-chain identity, a distinct parent-issued reviewer
identity, frozen artifact hashes, and parent-calculated false-negative and
false-positive counts. The Matt architecture vocabulary, CC review workflow,
and official Codex Security threat-model guidance are dated design inputs
only; those Skills were not executed and their value is not proved.

All positive cases and paired negative controls are rebound by file and result
hashes rather than copied into the stage evaluator.
The positive capture contains 7 stages, 8 authority receipts, 8 ledger
snapshots, 0 Agent dispatches, 0 model calls, no observed model route, no
parent-requested network access, Git mutation, or external write. The latter
three are parent reports, not system-level absence proofs: this calibration
had no network, process-wide filesystem, or Git mutation instrumentation.

Negative tests reject raw artifact tampering, missing receipts, authority
replay, Agent output relabelled as an authoritative source, same-identity
self-review, writes outside the allowlist, unknown telemetry coerced to zero,
schema/hash drift, omitted claim boundaries, and a zero-model capture claiming
a live route. They also reject syntax or the wrong test masquerading as RED,
implementation mutation before RED, architecture constraint/source/dependency
or unknown drift, a one-adapter hypothetical seam promoted to real, authority
overclaim, producer self-review, artifact drift, missed predeclared faults,
benign-canary false positives, a high finding hidden by a summary, private
oracle exposure, reviewer mutation, and a rehashed but semantically changed
domain-sub-oracle pack.

`valid-calibration-only` means the capture and evaluator mechanics survived
the frozen synthetic fixtures. It does not prove live Agent behavior, human
decision quality, production readiness, release or deployment, remote Git or
CI, dynamic MCP lifecycle control, cross-host portability, every software
lifecycle slice, candidate Skill value, a self-authored residual gap, or a
lossless end-to-end process.

The zero-model surface now justifies a separate request for one exact
disposable native `gpt-5.3-codex-spark` low run. This record does not start or
authorize that paid account-scoped model call. Before dispatch, the run must
bind one exact packet, the model route and usage boundary, effective sandbox,
parent-observed event trace, private-oracle isolation, and stop conditions.
The native baseline must precede any candidate Skill comparison. Real Git,
deployment, MCP, configuration, installation, cleanup, commit, and push remain
outside this record.
