# System And Manager Reference Cohort

## Decision

The three `system-or-manager-review-only` sources already present in the
bounded portfolio inventory have now received an exact-revision static review.
None enters the ordinary Skill candidate pool, replaces CC Switch, authorizes
installation, or proves runtime behavior or value.

The useful result is subtractive and compositional:

- reuse `skills.sh` discovery through CC Switch where suitable;
- retain selected consumer-topology, recovery, adapter, observability, and
  promotion-loop mechanisms as comparison inputs;
- reject whole-system installation or adoption as the default Harness path;
- keep repository-authored implementation behind a reproduced residual gap.

Machine evidence:
[`skill-portfolio-system-manager-reference-cohort-2026-08-06.json`](../../registry/skill-portfolio-system-manager-reference-cohort-2026-08-06.json).

## Bounded cohort

The source boundary was fixed before acquisition:

1. `stellarlinkco/myclaude`;
2. `vercel-labs/skills`;
3. `affaan-m/ECC`.

These are the three system or manager sources already named by
`skill-portfolio-inactive-source-candidate-pool-2026-08-02`. The cohort did
not search for more systems, inspect their Skill catalogs item by item, or
promote repository counts into coverage evidence.

The stop rule required one current default-branch revision, selected exact Git
object identities, lifecycle and authority findings, and one reference-only
disposition per source. Partial clones used a temporary operating-system root
outside all Agent, manager, and consumer discovery roots. The sources were not
checked out into the repository or any live Skill root, and no dependency or
third-party script ran.

## Source dispositions

### `stellarlinkco/myclaude`

The reviewed `master` revision remains
`f2e75c1263a2d5f09cdc4bb3dfe3635c635ff296`, unchanged from the prior source
inventory. It combines a user-root installer, global Claude Hooks, Skill
injection, multi-backend model execution, session resume, parallel execution,
worktree creation, and log cleanup.

The worktree, session, and rollback mechanisms are useful negative-control or
comparison inputs. Direct adoption is not eligible: the wrapper defaults the
Codex path to approval-and-sandbox bypass unless explicitly disabled, defaults
the Claude path to permission skipping unless disabled, installs into live
roots, can run configured commands, and carries AGPL-3.0 obligations.

Disposition: `architecture-and-negative-control-reference-only`.

### `vercel-labs/skills`

The reviewed `main` revision is
`a4d243c3d4f86cdf9385dd1b6a0733f6937e70b5`, package version `1.5.22`, thirteen
commits beyond the prior inventory pin. It maps many Agent roots, copies a
canonical body under `.agents/skills`, projects symlinks or copies, records
source and folder-hash state, and supplies `skills.sh` discovery.

The discovery and consumer-topology mechanisms are useful. The direct install
path is not CC-managed: it writes Agent roots, cleans destinations before
copying, may fall back from a symlink to an independent copy, and does not
establish CC database, backup, enabled-state, whole-cohort transaction, or
rollback evidence. Therefore `npx skills add` remains limited to isolated
inactive acquisition unless a separately reviewed adapter imports the exact
result into CC and verifies the managed lifecycle.

Disposition: `discovery-and-consumer-topology-adapter-input-only`.

### `affaan-m/ECC`

The reviewed `main` revision is
`623f2c020f052319657674e4e6c29ab5d0ad566b`, package version `2.1.0`, sixteen
commits beyond the prior inventory pin. Its reference architecture overlaps
several Harness questions: operator surfaces, host adapters, worktree and
session runtime, observability, evaluator loops, promotion, and rollback. It
also contains useful selective-install planning, dry-run, install-state,
repair, uninstall, adapter-compliance, and status mechanisms.

ECC is nevertheless a whole harness and distribution system, not one Skill or
one replaceable manager primitive. Its surface spans thousands of files,
multiple Agent roots, rules, Hooks, MCP templates, memory, plugins, Git hooks,
global configuration, external packages, hosted integration, and account or
credential boundaries. Its own documentation preserves host-parity and Codex
plugin-loading limitations. The source is therefore valuable as a set of
future exact mechanism comparators, not as a bulk-install or manager-replacement
candidate.

Disposition: `high-value-method-and-adapter-reference-only`.

## Claim ceiling

This checkpoint proves three dated default-branch revisions, selected Git
object identities, and a static mechanism comparison. It does not prove that
any source is secure, compatible, portable, loaded, invoked, behaviorally
effective, valuable, or production-ready. It creates no ordinary Skill
candidate, manager transaction, consumer projection, model run, new Harness
implementation, or hard standard.

The current 17-candidate pool remains unchanged. A future use of one of these
sources must bind an exact matching comparator need and preserve the same
separation between discovery, acquisition, installation, enablement,
instruction delivery, behavior, value, portability, and production claims.
