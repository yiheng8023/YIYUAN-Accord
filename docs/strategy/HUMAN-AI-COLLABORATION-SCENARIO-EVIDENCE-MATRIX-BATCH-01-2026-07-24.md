## Hard Gates And Upstream Capability Paths

Hard requirements are compulsory outcome and evidence gates. They remain valid
without AI, a model, an Agent, a Skill, or a Hook. They bind goals, truth,
authority, domain obligations, recovery, human accountability, and lifecycle
ownership.

Skills and other capabilities sit upstream. A native, official, reviewed
external, composed, human-expert, or later self-authored path may help pass a
hard gate, but it cannot replace that gate or its accountable owner. A
repository-authored path remains ineligible until repeated evidence shows a
material residual gap after the earlier routes are compared.

## Cross-cutting process fidelity

`XCR-01-process-fidelity-and-loss` applies to every scenario without increasing
the scenario count. It treats intake, interpretation, decomposition, routing,
tool or Agent delegation, context compression, handoff, aggregation, review,
acceptance, and lifecycle transitions as transformation edges.

Each material edge must preserve or explicitly reconcile goals, non-goals,
constraints, acceptance obligations, source identity, evidence lineage,
uncertainty, authority, data and permission boundaries, and current version or
repository truth. Planned evidence includes per-hop fingerprints and semantic
deltas, omitted constraints and added assumptions, cumulative loss budgets,
downstream blast radius, detection latency, recovery anchors, and adversarial
injection of a small upstream ambiguity. A local pass, unchanged tree, or fresh
handoff cannot prove end-to-end fidelity or losslessness.

Every scenario now binds the cross-cut explicitly rather than inheriting it
only from prose. The machine contract defines invariant survival, weighted
omission, added assumptions, provenance breaks, authority drift, detection
latency, amplification, recovery distance, and rollback success. Thresholds
are not universal: each experiment must preregister its applicable edges,
weights, oracle, stop condition, and last source-backed recovery anchor.

## Host And Evidence Split

Every scenario retains four host classes:

1. a host with transparent native state or telemetry;
2. a configurable Agent host with host-specific loading and precedence;
3. an opaque host requiring explicit unknowns and bounded heuristics;
4. a no-AI human control.

Documented capability is not live behavior. Configuration is not loading.
Loading is not adherence. A planned scenario is not evidence. Unknown host
behavior is not a residual capability gap.

Several rows now have bounded synthetic live Agent execution. For
`GEN-RESEARCH-01`, four v1 native Spark/low outputs satisfied the observed
