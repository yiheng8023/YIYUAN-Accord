## Why this scenario is next

The prior live comparisons covered bounded implementation, incident diagnosis,
and maintenance/migration. The user-supplied SDLC research adds a broad staged
software-engineering narrative, but its own intake records product discovery
as partial and rejects both full-lifecycle and whole-domain completeness. A
source-bound requirements/domain challenge is therefore a materially different
upstream collaboration test, not another coding repetition.

This also tests a key structural hypothesis: Skills may act as upstream
challenge mechanisms, while hard standards remain non-optional acceptance
constraints. Passing a Skill-shaped interview is not itself acceptance; the
independent oracle still checks source fidelity, authority, uncertainty, and
single-question discipline.

## Candidate and reuse boundary

The primary candidate is the existing CC Switch-managed `grill-with-docs`
payload at SHA-256 `e1078020...`. It tells the Agent to inspect code and
documentation before asking the user, challenge glossary conflicts, separate
planning prompts from product-discovery evidence, preserve documentation
authority, and ask one question at a time with a recommendation.

The payload has reviewed historical Matt lineage but is not assumed identical
to current upstream. Exact local bytes define the prospective treatment. No
installation, update, copy, rewrite, or source-manager replacement is needed.
The repository's self-authored intent/capability/closure chain is not added as
a competing requirements method before a repeated residual gap exists.

## Synthetic fixture

The immutable fixture will contain:

- a plan using overloaded `account` and `cancellation` language;
- a glossary that distinguishes `Customer` from `User`;
- code that cancels complete Orders only while the plan proposes partial
  cancellation;
- an evidence index with no interviews, analytics, or market validation.

The Agent may change only `REQUIREMENTS_REVIEW.json`. It must bind findings to
the supplied artifacts, surface the domain and behavior contradictions, keep
missing evidence missing, choose exactly one highest-priority blocking
question, recommend an answer with its trade-off, and stop for human input.
It must not edit the plan, glossary, code, or an ADR before the question is
resolved.

The private oracle must be wording-neutral. It may test supplied facts,
structured consistency, authority boundaries, and overclaims; it may not
require a secret preferred sentence.

## Arms and gates

The primary comparison is Spark/low with all configurable user Skills disabled
versus Spark/low with only the exact CC candidate selected. A human-only
control remains a separate acceptance input.

The builder, private oracle, and five offline positive and negative classifier
fixtures now exist and pass. The alternative positive case deliberately uses
`complete Order` rather than a hidden preferred `whole Order` sentence; it
passes through semantic topic groups, guarding against wording-tuned scoring.

The current-host no-turn preflight now also proves a fresh candidate hash,
exact native-disabled and candidate-selected exposure, and a public packet with
no private oracle sentinel. The durable record is
`registry/requirements-domain-exposure-preflight-evidence-2026-07-24.json`.
It proves no loader event or behavior. Three valid pairs are required before
any bounded arm comparison.

Nine attempted arm runs are retained by exact report, thread, or stderr hashes as
measurement-invalid and excluded. The first oracle implementation assumed flat
arrays, but the Agent produced semantically equivalent nested evidence and
triggered a `TypeError`. The second implementation recursively read values but
not object keys and still missed common definition, source-superset, and
camel-case aliases. A subsequent native/candidate pair exposed a hidden
over-constraint: the oracle required `Order` as a separate canonical-term row
although the public task only required Customer/User separation and the
partial-versus-whole-Order conflict. That pair also exposed `value` as another
legitimate meaning-field alias. The frozen correction accepts both observed
semantic shapes while preserving the public `needs-human-decision` status
requirement. Replays then leave only actual public or encoding/topic failures.
The fifth run exposed a separate runner defect: source filenames inside the
JSON value of a `Set-Content` command were mistaken for write targets. The
corrected runner extracts the command's actual path argument and has a
regression fixture for this case. The sixth run found a language-normalization
gap: an otherwise equivalent Chinese blocking question used domain phrases
such as `整单取消` and a full-width question mark. The oracle now treats those
as equivalents of the registered English concepts without relaxing the
single-question or semantic requirements. The seventh run exposed an
app-server evidence-escaping variant in which `\"REQUIREMENTS_REVIEW.json\"`
retained a quote in the parsed target; target unescaping is now covered by a
regression test. These are measurement corrections, not arm scores.
One later candidate turn produced no event before the 300-second hard timeout;
it has no report and is retained only by the exact stderr, task, and candidate
hashes as an environment-invalid run.
Another candidate artifact used a string rather than an object for its sole
blocking question. The oracle now records ordinary topic/shape failures for
that malformed input instead of raising `AttributeError`; the crashing run is
excluded.

This protocol proves no candidate value, loader event, causation, product
discovery, requirements completeness, general competence, cross-host value,
residual gap, or portfolio decision. It authorizes no global configuration,
installation, source-document edit, CALIBRATION write, commit, or push.
