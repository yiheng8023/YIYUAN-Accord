### 2026-07-31 tree-identity reconciliation

The static triage and the later live manager preflight used the same ordered
file records but encoded each record differently before hashing. This document
used `relativePath<TAB>bytes<TAB>fileSha256`, while the live preflight used
`relativePath<NUL>bytes<NUL>fileSha256`; both join records with LF after
case-insensitive path ordering. Their digest strings therefore must not be
compared directly.

The registry now names both algorithms and forbids direct cross-algorithm
digest comparison. A future manager preview must re-encode the same file
records with one declared algorithm before deciding whether a tree drifted.
Matching file count, total bytes, or `SKILL.md` hash remains supporting
evidence, not a substitute for that canonical comparison.

## Source and carrier findings

### Retain: `obsidian-open-format-knowledge-files`

The live body is byte-equal to the repository-approved payload. Its declared
Kepano source pin,
`a1dc48e68138490d522c04cbf5822214c6eb1202`, is still current `main`. The
adaptation is agent-neutral, dependency-free, and explicitly separates open
Markdown, JSON Canvas, and Bases file work from live Obsidian, CLI, plugin,
vault, and rendering control. That is a bounded portable increment over
generic file editing.

### Preview removal: `disciplined-coding`

The row is local and unattributed. No current Matt path exists for this name,
so historical documents that called it a Matt-family treatment do not bind
source authority. Its Karpathy-style restraint, minimal-diff, assumption, and
verification rules substantially overlap active native/rules behavior and
Matt implementation/review Skills.

The historical Spark/low fixture is bounded evidence against assuming value:
both native and candidate arms passed the functional oracle, while the recorded
strict process passed native 3/3 and candidate 2/3; one candidate run made a
transient out-of-scope write. Loader delivery and causation were not proved.
This does not prove the Skill harmful, but it leaves no evidenced incremental
value strong enough to justify an unattributed permanent active copy.

### Preview removal: `migrate-to-shoehorn`

The live body is byte-equal to the approved repository payload, so removal from
the active manager would not erase the reviewed payload. Current Matt `main`
keeps the upstream Skill only under non-promoted `misc`, and the live adapted
body is not current-upstream exact.

Its scope is a narrow TypeScript test-only migration and it introduces
`@total-typescript/shoehorn`. The public npm record currently reports version
`0.1.2`, MIT, last modified 2024-02-26. With no bound migration task or
behavioral value trial, this belongs in on-demand approved inventory rather
than the permanently exposed shared set.

### Preview removal: `obsidian-vault`

Current Matt classifies the source under personal, not promoted. The live body
is a local derivative that removes Matt's private path but preserves a
flat-vault and naming convention. Neither a repository `.vault-path` nor a
`VAULT_PATH` environment entry is present.

The retained open-format Skill covers portable file semantics without those
personal assumptions. A live-vault adapter should be selected only after a
vault, path, structure, write authority, and verification surface are bound.

### Preview removal: `playwright`

The nine-file live tree matches current `openai/skills` `main`
`49f948faa9258a0c61caceaf225e179651397431` after line-ending normalization.
This is not a low-quality body. The problem is carrier placement: it is an
OpenAI-official, Codex-home-coupled copy vendored into the shared CC store.

The wrapper has `npx` available but no globally installed `@playwright/cli`;
invocation would dynamically acquire the package. The current host already
exposes installed browser and Chrome control Plugins plus live Playwright MCP
tools. Official metadata can remain recorded without keeping this duplicate
shared active copy.

### Preview removal: `security-ownership-map`

The eight-file live tree also matches the same current OpenAI revision after
line-ending normalization. Its code is substantial and useful for a concrete
security ownership or bus-factor task, but the current Python environment does
not contain its required `networkx` dependency.

It also crosses a larger data boundary: full Git history, contributor
identities, sensitive-path classification, and people-to-file output. No
current task binds that data boundary or supplies dependency-complete behavior
evidence. Keep the official source metadata and reacquire it only for a
specific authorized ownership-risk analysis.
