## Common Ground And Conflict

Both candidates require behavior tests through public interfaces, independent
literal expectations, a valid RED observation before minimal production code,
and restraint around internal mocks.

Matt additionally requires the test seam to be pre-agreed with the user,
rejects horizontal all-tests-first slicing, and moves refactoring to a later
review stage. Superpowers treats verified RED as an iron law, permits
refactoring after GREEN, and explicitly asks what realistic production
mutation each test catches.

The task packet will therefore pre-accept one public seam, avoiding an extra
Matt interaction. The fixture will require no meaningful structural refactor.
Whether a no-op or optional refactor event occurs is recorded but not scored.
This prevents the incompatible refactor-stage rules from deciding the
functional result.

## Hard Gates

Every primary arm receives the same prompt, fixture, oracle, model route,
sandbox, file allowlist, and hard acceptance:

- the visible and parent-owned hidden behavior oracle passes;
- the parent can order a valid focused RED before the first production-code
  mutation;
- the Agent-authored tests kill every predeclared realistic mutant;
- tests use the pre-agreed public seam and independently derived expectations;
- no out-of-scope file, dependency, network, Git, configuration, Plugin, MCP,
  or external write occurs;
- no production, causation, or superiority claim is made.

Final green tests without an ordered RED-to-production timeline are
measurement-invalid, not a TDD pass. Syntax, import, path, and harness errors
do not count as RED.

Command count, correction loops, response size, and refactor events are
secondary observations. They cannot override a hard-gate failure.
