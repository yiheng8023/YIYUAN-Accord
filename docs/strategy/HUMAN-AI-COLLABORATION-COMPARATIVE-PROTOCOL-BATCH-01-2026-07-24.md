# Human-AI Collaboration Comparative Protocol — Batch 01

Date: 2026-07-24
Status: second software three-pair threshold met; association observed, causation unproved; Superpowers blocked

## Selected Scenarios

The first general scenario is `GEN-RESEARCH-01`. It uses a fixed synthetic
source packet and a private claim oracle. This gives high-quality evidence for
source entailment, contradiction, uncertainty, omission, and unsupported
conclusions without accounts, private data, publication, or a subjective
creative judgment.

The first software scenario is `SE-IMPLEMENT-REVIEW-01`. It uses a
dependency-free disposable Python fixture with visible and hidden behavior,
an exact file allowlist, and process evidence. It can distinguish correctness,
scope restraint, dependency changes, and witnessed test order.

The second software scenario is `SE-OPS-INCIDENT-01`. It uses a dependency-free
synthetic multi-tenant policy cache. Each tenant is correct in a fresh process,
but reading tenant alpha before tenant beta exposes a cache-key isolation bug.
This retains a programming-heavy task while adding exact-symptom reproduction,
root-cause attribution, unsafe-workaround rejection, recovery verification,
uncertainty discipline, and cleanup. The private oracle rejects disabling or
clearing the cache, tenant-name special cases, default changes, and recovery
claims made without rerunning the original cross-tenant sequence.

Selection is qualitative and ordinal. The project does not optimize scenario
counts or manufacture numerical precision from judgment calls.

## Suitability Before Arms

Candidates are not forced into a benchmark merely because they are installed.

- Matt's `grill-with-docs` is excluded from the research arm. It is an
  interactive, one-question-at-a-time plan and domain-model grilling workflow
  that may write `CONTEXT.md` or ADRs. That would add user-interaction and
  repository-write confounds, and it is not a fixed-source synthesis method.
- Matt's `disciplined-coding` is eligible for the first software arm because
  its explicit claims—assumption control, minimal diff, behavior preservation,
  and verification—fit the fixture.
- Superpowers' `test-driven-development` is eligible because its additional
  RED-before-production-code rule is directly observable.
- Matt `review` and Superpowers `requesting-code-review` are deferred to a
  separate review phase. Both add fixed-point/spec or reviewer-subagent
  orchestration that would confound the first implementation comparison.
- The installed CC `diagnose` payload is eligible for the second software
  scenario after exact candidate-specific exposure was proved. Its bytes
  exactly match Matt upstream commit `7afa86d3a5dd96edde06ffa014e16c64e733681e`,
  but not current Matt `main`. Current upstream renamed it to
  `diagnosing-bugs` and strengthened the tight-loop, red-capable, and minimal
  reproduction conditions. Results from the installed payload must therefore
  be labeled as the historical deployed version, not current Matt.
- Superpowers `systematic-debugging` is content-suitable but host-selection
  blocked. It requires root-cause investigation and one hypothesis tested
  minimally at a time. The installed historical Matt payload instead asks for
  3–5 ranked falsifiable hypotheses. This is a real process conflict to
  observe, not wording to merge before evidence.
- The self-authored `intent-contract`, `capability-router`, and
  `closure-contract` are phase controls, not one coding method. A fair combined
  arm needs phase attribution and task-scoped multi-Skill exposure, which are
  not yet proved.

This is a negative result where appropriate: excluding an unsuitable candidate
is preferable to generating a misleading comparison.

The second software scenario has now completed three native versus installed
historical `diagnose` pairs under `gpt-5.3-codex-spark/low`. Both arms passed
the functional oracle in all three repetitions. The native arm passed the
strict process boundary zero times; `diagnose` passed twice. The differences
were one native out-of-scope memory read and three red-before-green misses

but no independent loader event or exact installed-`diagnose` delivery event
was observed. Identical incident and canary repetitions stop here.

## Weak-Agent Arms

The primary model request is `gpt-5.3-codex-spark` with `low` reasoning.
`gpt-5.4-mini/low` is a secondary weak diagnostic. A strong diagnostic uses
`gpt-5.6-terra/high` only after a predeclared attribution problem; it cannot
replace weak-Agent acceptance.

`GEN-RESEARCH-01` uses the dedicated
`scripts/run_human_ai_collaboration_read_only_claim_trial.py` runner rather
than the coding runner. The public packet is injected directly into one
ephemeral read-only turn, while the private oracle stays in the harness
process. Commands, file changes, MCP or dynamic tool calls, multiple Agent
messages, fenced or trailing response content, and unknown item types all fail
the run. Static MCP names and plugin features are disabled for the observed
host, but that list does not prove complete MCP inventory or the absence of
unobserved transient writes or network activity.

The planned software comparison contains:

1. all user Skills disabled;
2. only Matt `disciplined-coding` enabled;
3. only Superpowers `test-driven-development` enabled.

Every arm keeps the same repository instructions, fixture, prompt, private
oracle, model request, sandbox, and hard requirements. The TDD arm alone has
the additional requirement that a failing test is observed before production
code.

The native all-user-disabled exposure has been observed on Codex `0.145.0`.

## Self-Authored Chain Boundary

The three self-authored Skills are not removed from analysis. Their fair unit
of comparison is different:

- `intent-contract` is judged at intake;
- `capability-router` is judged at route selection and reroute checkpoints;
- `closure-contract` is judged at evidence-backed closeout.

Treating the three together as a single coding payload would confound context
size, phase value, and loader exposure. The current batch records this as an
open orchestration question rather than crediting or penalizing the chain.

## Evidence And Authority

The synthetic research packet permits only one structured JSON response. The
software fixture permits writes only inside an isolated fixture and local
Python tests. Neither protocol permits network access, account access, MCP or
App use, dependency installation, global configuration writes, commits,
pushes, or external communication.

A result classifier rejects:

- missing, extra, miscited, or misclassified research claims;
- unsupported conclusions or external access;
- failing visible or hidden software tests;
- out-of-scope files, dependency changes, network or Git mutation;
- a Superpowers TDD arm without witnessed RED-before-code evidence;
- dispatch of excluded, deferred, or conditional arms;
- strong diagnostics without the attribution trigger.

Passing classifier fixtures prove the offline decision contract only. They do
not prove model identity telemetry, Skill invocation, task quality, superiority,
production readiness, or cross-host value.
