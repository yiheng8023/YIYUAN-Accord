## Reopened live-mechanism decision

Exact historical baseline `ae729465` includes an earlier stateless
`SessionStart` context Hook. The current main bytes are an unreleased working
projection that replaces its echo with a shared short-lived Node event adapter
and changes its matcher; specifically, the working projection removes the earlier Claude
`fork` matcher and covers the currently documented new, resumed, cleared and
compacted session sources. These current bytes are not attributed back to the
historical revision. The adapter uses the package's shared behavior module,
requires a sufficient native or simple route to stay silent, reads no
transcript, writes no state, starts no background process and depends on a
host-path Node executable rather than an Accord-managed Runtime. `startup` and
`clear` stay silent. `compact` and `resume` emit only non-authoritative event
hints plus a requirement for permitted task-time re-sensing before receipts or
allocation; invalid input fails visibly without echoing it. The injection is
not a live receipt, Agent use, execution, consequence, evidence or value.

No SessionStart `fork` matcher is claimed. A copied-history fork remains a
causal branch rather than a handoff or context-relief mechanism. Compact is
same-carrier memory reduction; causal fork is
copied-history branching; sequential load relief requires a fresh zero-history
conversation carrier, minimum verified state transfer, destination verification
and only then source release. None of these conversation operations changes
checkout, branch, worktree, repository fork or local/cloud execution placement.

This is only a dormant working-projection activation hypothesis, not a candidate
definition, firing or outcome evidence. Codex requires explicit
trust for the exact current non-managed Hook definition and repeats that review
when its hash changes. Claude currently supports in-session plugin reload;
equivalent active-session Codex hot reload is not established, so update and
rollback remain host-capability-conditioned rather than falsely uniform.

Only this provisional short-lived event adapter is selected for GT-21 treatment;
the final live mechanism set remains undecided. The evidence order is direct official
query and action surfaces, then a synchronous event Hook for invalidation,
re-sensing and pure-core invocation, then bounded plugin-private state for a
demonstrated cross-event duty, then bundled MCP or an equivalent typed actuator
for a remaining gap. An SDK, App Server client or persistent service is admitted
only after those lower-burden routes fail the same GT-21 oracle. The active
development task does not hot-load mutable working-projection bytes and cannot serve as
its own baseline.
