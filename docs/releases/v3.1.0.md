The candidate reopens the product at the collaboration-model boundary. It does
not define Accord as a capability set difference. Finite autonomy derives the
smallest relevant graph across outcome obligations, people, Agents,
capabilities, carriers, authority, evidence, state, resources, effects and
lifecycle; it then closes unfulfilled or unreliable relations through the
lowest-total-burden feasible authorized path. A capability gap remains a local
diagnostic view, not the product definition. More host adapters are not a
substitute for consequence-level outcome delivery.

Product-form neutrality remains dynamic rather than form-indifferent. A plugin
or Skill is neither presumed sufficient nor declared inadequate by identity.
Named responsibilities may be closed by one form, several replaceable forms or
no Accord-owned artifact; shared outcome, authority, evidence and lifecycle
contracts provide system coherence without preselecting a Runtime or state
layer.

This also raises three explicit assurance pressures from external review of the
immutable v3.0.1 release: a declared contract must be connected through
activation, execution, effect and evidence rather than mistaken for enforcement;
internal rule identifiers and machine-readable authority records must not become ordinary-user cognitive load;
and cross-session continuity must bind an observed state carrier rather than
pretending static instructions are current state. The review is an input, not
proof of current behavior.

The baseline's current-Skill Codex-local GT-07, GT-11, GT-12 and GT-13 observations
pass their bounded Windows tasks or workspaces and independently verified cleanup. GT-13
is a single-arm dogfood result for the product-definition correction; it is not

implicit invocation, current-session hot reload, Claude, client, Cloud,
cross-host, field-value and production behavior remain unproved. Released
v3.0.1 observations remain historical inputs rather than inherited proof.

## Selected first mechanism

The historical baseline Codex and Claude packages include one stateless
`SessionStart` context Hook. It is configured to emit a compact activation
reminder on supported new, resumed, cleared and compacted sessions; Claude also
covers a forked session. The reminder points nontrivial or stateful outcomes to the shared
`deliver-demand-driven-outcome` Skill, requires a sufficient native or simple
route to stay silent, reads no transcript, writes no state, starts no background
process and adds no interpreter dependency.

This is only a candidate activation definition, not firing or outcome evidence. Codex requires explicit
trust for the exact current non-managed Hook definition and repeats that review
when its hash changes. Claude currently supports in-session plugin reload;
equivalent active-session Codex hot reload is not established, so update and
rollback remain host-capability-conditioned rather than falsely uniform.

## Prospective finite claim ceiling

Only after every declared gate passes on one unchanged exact revision may the
candidate claim:

- Context-adaptive collaboration-closure conformance for v3.1.0.
- Static package conformance for the current Codex and Claude projections.
- One bounded single-arm collaboration-closure dogfood result.
- Replayed local regression results for continuity, repair and resource stewardship.
- Reproducibility from a clean v3.1.0 checkout.

It does not imply:

- Universal correctness for human-AI collaboration.
- Universal or unbounded Agent autonomy.
- A complete or permanent capability inventory.
- Broad field effectiveness.
- Comparative burden reduction across populations.
- Equivalence across Agents, hosts, clients, models or providers.
- Automatic activation on every message.
- Current-session hot reload that was not directly observed.
- Automatic whole-system resource optimization or reclamation.
- Longitudinal human or organizational outcomes.
- Domain-professional correctness.
- Production deployment safety.
- A release tag or publication before every exact gate passes.
