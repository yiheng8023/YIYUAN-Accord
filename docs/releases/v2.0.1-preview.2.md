# YIYUAN Accord v2.0.1-preview.2 — Unreleased historical checkpoint

This document preserves the bounded intent and counterevidence of an unreleased
distribution checkpoint. It does not grant current candidate, publication or
release authority.

## What the checkpoint explored

- Host-consistent human presentation as `YIYUAN Accord for Codex` and
  `YIYUAN Accord for Claude`, while retaining stable technical package IDs.
- An official Claude marketplace catalog and a distinction between persistent
  marketplace installation, session-only direct loading, repository cloning,
  enablement, Skill visibility and effective behavior.
- Fail-closed validation of the Claude display name, marketplace source,
  description and package version.
- A bounded local lifecycle replay for installation, enablement, explicit Skill
  discovery and direct invocation.

The checkpoint added no Runtime, Hook, MCP server, App, state store, background
process or automatic user-configuration mutation. That was a fact about this
checkpoint, not a permanent product prohibition.

## Why the route was retired

Before publication, the product premise was corrected from a thin portable
contract plus fixed runtime-free projections to a small portable reliability
kernel plus context-adaptive, mechanism-neutral outcome delivery. The old
distribution route therefore no longer represented the intended product well
enough to become the next public recommendation.

The package tree, evaluation attempts and failures remain provenance. They do
not become current evidence merely because the files remain in Git history or
in a local plugin cache.

## Historical claim ceiling

Had this checkpoint proceeded, its proposed finite claims would have been:

- `canonical-yiyuan-accord-identity-conformance`
- `portable-human-agent-collaboration-contract-conformance`
- `thin-codex-and-claude-projection-conformance`
- `bounded-representative-help-and-interference-results`
- `clean-checkout-reproducibility`

It would not have implied:

- `universal-human-ai-collaboration-correctness`
- `broad-field-effectiveness`
- `comparative-burden-reduction-across-populations`
- `all-agent-or-all-host-equivalence`
- `longitudinal-human-or-organizational-outcomes`
- `domain-professional-correctness`
- `production-deployment-safety`
- `every-golden-task-or-host-projection-passes`

Nor would it have implied automatic invocation after installation.

The retained behavior exclusion was
`retainedBehaviorExclusions=["GT-07:cleanup"]`.
