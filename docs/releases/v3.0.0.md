# YIYUAN Accord v3.0.0

YIYUAN Accord v3.0.0 is the first full release of the adaptive product shape:
a small portable reliability kernel plus context-tailored, mechanism-neutral
outcome delivery. The major version records an incompatible product-boundary
correction; it is not a claim of universal correctness or production safety.

## What changed

- Goal, requirement, capability, authority, evidence and cost now drive a live
  route through context, state, effect, continuity, topology and lifecycle.
- Codex and Claude expose the same `deliver-demand-driven-outcome` Skill name
  and the host-qualified human names `YIYUAN Accord for Codex` and
  `YIYUAN Accord for Claude`.
- The progressively disclosed Skill discovers current capabilities, can use
  reliable official or external sources when native and marketplace surfaces
  are insufficient, owns supported configuration and topology mechanics,
  recomputes on drift, and prefers native hot reload or atomic update with
  health check and rollback.
- Installation remains latent availability, not unconditional per-message
  activation. A healthy sufficient native route is a correct no-op.
- Skill, plugin, App, MCP, Hook, configuration, state, runtime, cloud carrier or
  another mechanism is neither mandatory nor permanently forbidden; every
  mechanism remains scoped, observable, reversible and retireable.
- Schema v3 authority, the derived dynamic-relation model, fail-closed verifier,
  GT-11 adaptive outcome evaluation and complexity/process-loss controls replace
  the retired preview.2 release premise without moving historical tags.

## Install

Codex:

```powershell
codex plugin marketplace add yiheng8023/YIYUAN-Accord --ref v3.0.0
codex plugin add yiyuan-accord-codex@yiyuan-accord
```

Claude Code:

```powershell
claude plugin marketplace add yiheng8023/YIYUAN-Accord@v3.0.0
claude plugin install yiyuan-accord-claude@yiyuan-accord
```

For Claude Desktop Chat, Claude web chat or Cowork, add the Accord GitHub
repository under **Customize > Plugins**, install **YIYUAN Accord for Claude**,
start a new chat and confirm `deliver-demand-driven-outcome` is visible.

Start a new task or session after installation. Installation and enablement do
not prove activation or behavior; explicit Skill selection is only needed for
a deterministic exposure check.

## Evidence boundary

The current representative behavior claim is limited to the exact Codex-local
GT-11 repair, correction, route degradation, no-op, update/rollback and cleanup
observation bound to the v3 Skill. Claude Code autonomous closeout and current
Claude client behavior remain unclaimed; static package validation is not
promoted into behavior equivalence.

The first Windows atomic-update fixture failed because its implementation
called `fsync` on a read-only descriptor and left one transaction file. That
failure remains recorded as `FC-V3-01`; replay from the fixture implementation
boundary passed health failure, byte-exact rollback and cleanup. This is not
evidence of live host-plugin hot update.

The full-release candidate requires an unchanged clean SHA to pass canonical
and independent local review, Ubuntu/Windows/macOS GitHub Actions, ordinary
Codex Cloud verification and a separate named-human decision before tagging.

## Release integrity

The release uses one lightweight `v3.0.0` tag, a non-prerelease GitHub Release
and no attached assets. Existing `v2.0` and `v2.0.1-preview.1` tags remain
immutable; `v2.0.1-preview.2` remains an unreleased historical checkpoint.
