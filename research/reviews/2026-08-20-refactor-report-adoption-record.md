## First live calibration after adoption

The first bounded-help task, GT-02, confirmed rather than weakened the report's
warning about repair-by-addition. Codex completed the intended source change,
kept unrelated dirty state and passed the focused test, but left two Python
cache files without disclosure. One minimal same-purpose Skill addition did not
change that behavior, so it was removed under L2 instead of becoming another
layer. The failed observation remains in the required v1.2 sample and blocks
the exact Codex cleanup-behavior claim.

This also exposed a category distinction not explicit enough in the report:
an evaluation harness can correctly detect and preserve a failed host task
without every evaluated behavior passing. The release remains bounded to the
Harness contract, current thin projections and honestly retained sample
decisions; it cannot claim that the failed Codex behavior is qualified.

## Shared shortfall research reconciliation

The separate YIYUAN-CALIBRATION packet was reviewed rather than inferred from
the project audit. Its seven invariant candidates map into the current kernel:
versioned goal (K1), bounded authority (K3), consequence-proportional evidence
(K5/L4), untrusted data not instruction (K1/Q2), traceable and recoverable
effects (K4/K5), externally supported closure (K5/Q2), and serious or repeated
failure changing the system (K4/L2/L7).

The packet's three temporal contracts and four control planes remain a held
architecture hypothesis, not a proven minimum or seven-feature backlog.
Likewise, its detailed problem taxonomy is diagnostic input for Golden Tasks,
not a mandate to create one product mechanism per shortfall. This preserves its
warning about over-control and keeps product complexity proportional.

## Current upstream boundary

The official Codex sources reviewed for this decision describe isolated cloud
environments and review-before-merge, progressively disclosed Skills,
long-running work practices, and the App Server protocol. They support using
cloud as a distinct exact-host evaluation lane and keeping host mechanics in a
thin projection. They do not establish a universal 60/80 context threshold.
