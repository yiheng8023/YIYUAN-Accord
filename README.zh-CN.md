# Agent Autonomy Harness

[English](README.md) | 简体中文

Agent Autonomy Harness 是一个 Agent 中立产品：它在真实任务中保持目标、能力路线、
授权边界、生命周期、连续性、证据和清理的一致性，而不是让用户亲自编排每个 Agent、
Skill、MCP、Plugin、Hook、线程、工作树和管理器。

本产品不是“大而全的 Skills 列表”。外围能力是可替换的输入和适配器；Harness
负责判断何时需要它们、授予什么边界、怎样观察效果以及何时释放。

## 当前产品状态

- 版本目标：`v0.1`；
- 产品结果：已验证 `3/5`；
- 强制护栏：通过 `4/4`；
- 当前唯一因果增量：`increment.product-control-reset`；
- 总体仍为 `in-progress`：O3 能力生命周期和 O4 新任务连续性尚需真实产品切片。

本次主线重置本身就是用户提供的真实任务。它暴露了真实 Harness 缺陷：旧的研究与
策展程序可以持续全绿，而产品交付、用户负担和清理并不控制下一步。新的产品控制
seam 会拒绝无验收映射的工作、多个活动增量、活动表面的前身权威，以及把护栏计入
产品进度的做法。

## 当前机器权威

- [项目宪法](product/constitution.json)：目的、固定不变量、可适应表面和规划方法；
- [产品工序](product/program.json)：一个活动因果增量和有限的后续增量；
- [产品验收](product/acceptance.json)：五项产品结果和四项强制护栏；
- [架构](docs/architecture.md)：可移植核心、生命周期平面、宿主适配器和消费者投影。

历史研究、fixtures、registries 和回归工具仍可从 Git 历史精确取回，但不具有当前
产品、规划、验收、运行时或发布权威；宿主策略阻止删除的本地忽略隔离区也不会改变
这一边界。

## 验证

```powershell
python -B -m harness verify --root . --json
python -B scripts/verify.py
python -B -m unittest discover -s tests/product -v
```

PASS 只证明当前计划、验收映射、证据绑定、授权边界和身份门禁内部一致；它不证明
O3、O4、跨宿主行为、生产就绪、发布就绪或广泛用户价值。

## 实施方法

项目采用“固定产品宪法与验收 + 短周期因果导引”的混合方式：

1. 固定目的、产品边界、授权底线和版本验收；
2. 同时只允许一个短因果增量；
3. 每个增量必须声明观察到的问题、因果假设、证伪条件、验收映射和有限停止条件；
4. 实施并观察最小产品切片；
5. 只有证据改变因果模型或增量结束时才重排计划。

研究、生态发现、库存增长、静态审查、零模型 fixture 和测试数量可以支持产品结果，
但它们本身永远不计入产品进度。

“最小充分”按需求覆盖判断，不等于追求最少能力数。有边界的组合策展增量可以主动
比较候选并把精确版本获取到非活动审查池；真实安装、启用、账号连接和消费者投影仍
是独立授权迁移。

## 能力选择顺序

对已经绑定的需求依次优先使用：健康的原生/运行时能力、合适的官方能力、已审查且
维护良好的外部实现、现有能力组合；只有可重复的剩余缺口才允许仓库自研。

安装、启用、账号连接、真实 dispatch、消费者修改、验收、发布和公开分发始终是
不同状态迁移。

- `docs/`：当前架构、触发式研究计划和精简接续；
